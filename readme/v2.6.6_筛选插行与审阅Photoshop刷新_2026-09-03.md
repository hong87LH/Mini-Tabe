## rev3 补充：刷新使用同尺寸系统缩略图（当前行为）

用户发现刷新后缩略图变清晰。核查原因是第一轮刷新读取完整原图、用 Canvas 生成最长边 400px 的缩略图，而首次加载优先使用系统 150×150 缩略图。现按用户要求统一：

- 首次加载与审阅刷新共用 `SYSTEM_THUMBNAIL_SIZE`（150×150 尺寸框，保持图片比例，并非强制拉伸为正方形）。
- 审阅刷新直接调用现有 `electronAPI.getThumbnail` → `get-thumbnail` → `nativeImage.createThumbnailFromPath`，绕过应用自身的旧缩略图缓存，重新请求系统缩略图。
- 不再调用 `readLocalFile`，不在 Renderer 解码原图、不生成 400px Canvas、不下载远程原图、不新建原图 Blob。这里限制的是应用刷新链路；系统内部如何生成缩略图由系统服务负责。
- 成功后替换缩略图、更新异步缓存修订号；已有原图 Blob 缓存仅失效释放，不预先加载原图。大图仍由打开预览时的原有链路处理。
- 系统不支持该文件、文件缺失、非本地地址或浏览器版没有 Electron 接口时，保留旧缩略图并提示失败，不回退读原图。这意味着网络图片不再通过本刷新按钮下载更新。
- 仍限定当前可视图片、同源路径去重、最多两个并发请求；不改生产记录、路径、评分、批注、裁切或生成配置。
- 本轮修改 4 个文件：`src/components/Grid.tsx`、`src/lib/reviewMedia.ts`、`tests/review_media.test.ts`、本报告。`main.js` / `preload.js` 不改，无需重启主进程或改变 API 启动命令。

## 1. 筛选状态下向上／向下插入

原问题：Grid 将筛选后的行序号交给 App，App 却把它作为完整 records 数组的插入位置，造成错位；新空行也可能立即被筛选隐藏。

现在：菜单传递真实 recordId 和 above/below，App 在最新完整 records 中查找锚点再插入。锚点已不存在时不执行，不会退化为末尾追加。支持一次插入多行，且不复制原行的提示词、附件、评分、批注或 Cell Link。

### 筛选与空行的规则

- 单选标签的明确等值条件，或只包含一个目标的“指定值”条件：预填已有选项 ID。
- 普通文本、URL、日期和数字的可确定值：只有能满足该字段全部筛选约束时才预填。
- “包含”“不等于”“非空”“多个值任一匹配”等无法唯一推导的条件：不猜值。AI／公式／附件字段不自动填充。
- 不符合筛选的新行暂时显示，并在表格上方提示“重新应用筛选”。它们已是真实记录，保存、撤销仍走原有数据链路，不是虚拟行。
- 点击“重新应用筛选”，或切表／切视图／改变筛选／刷新页面后，恢复严格筛选。不匹配记录只隐藏，不删除。
- 临时显示名单只在当前界面会话中，不写入工程文件，不影响其他用户或 API 的持久数据。
- 开启排序／分组时，视觉位置仍受排序／分组控制；完整表的底层插入位置依然紧邻指定记录。不擅自关闭排序或复制分组字段。
- 本轮优化的是行菜单的向上／向下插入；工具栏和底部的通用“添加行”保持原行为。

产品参考：Airtable 官方明确说明，新记录可以继承当前单选筛选条件或分组中的单选值；这不代表所有复杂条件都有唯一默认值。

https://support.airtable.com/articles/1905277605-single-select-fields-in-airtable

## 2. 审阅图片的 Photoshop 入口

- 图片缩略图左下角增加小型 Ps 角标，沿用现有卡片尺寸和样式，避开右上角审核状态及下方评分／文本。
- 点击只打开原图，不触发卡片大屏预览。
- 使用现有 electronAPI.openInPhotoshop 和 bitable_ps_path 设置，不增加新的主进程协议。
- 仅桌面版的本地图片可用；网络图和浏览器版禁用并提示原因。视频／音频不显示此角标。
- 未配置 Photoshop 路径时提示用户配置，不在前端默默改用其他程序。
- 打开的是本地原始文件，保留现有 Crop 的非破坏性语义，不自动导出裁切副本。

## 3. 第一轮刷新可视图片（历史实现，已被 rev3 覆盖）

审阅筛选栏右侧、图片数量之前新增刷新按钮。

- 按点击时的实际可视区域取图片路径。被筛选隐藏、折叠组内、滚动区域外和视频／音频均不处理。
- 同源路径去重，最多同时读取／解码两张图片。
- 本地文件通过现有 readLocalFile 读取最新字节，绕过 Windows 缩略图服务和浏览器旧文件缓存；网络图使用 no-store 获取。
- 成功后更新内存缩略图与大屏预览 Blob，同时防止旧异步缩略图任务覆盖新缓存。
- 失败项保留原缩略图并报告失败数量。刷新不改路径、附件对象、评分、批注或 cropData／trimData，也不占用撤销步骤。
- 支持浏览器能解码的常见图片格式；PSD／部分 TIFF、HEIC 等即使可由 Photoshop 打开，也不保证 Chromium 能解码刷新。失败会明确提示。
- Photoshop 中必须先保存回原文件。若另存为新路径，不会猜测或自动替换表内地址。

## 6. 建议的人工验收（约 1 分钟）

1. 在有本地 PNG/JPEG 的表中进入图片审阅，确认 Photoshop 路径已配置。
2. 点左下 Ps 角标，确认只打开 Photoshop、不打开表格大屏。
3. 在 PS 中修改一张测试副本并保存回原地址。
4. 回到审阅界面，点刷新；核对缩略图和点击后的大图都更新，评分／批注仍保留。
5. 折叠另一组，或滚动到只看到部分图片，再刷新，检查处理数量只包含当前可视图片。
