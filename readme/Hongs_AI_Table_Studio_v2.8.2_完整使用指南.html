Hong's AI Table Studio v2.8.2

完整使用指南 · 2026-11-24 · Electron 桌面端

本指南按实际使用路径组织，不把 v2.8.2 的智能裁切能力作为孤立更新附在文末。普通用户先看第 2～6 章；需要调整裁切效果的维护者重点看第 7～9、12 章。

1. 工具与本版重点

AI Table Studio 把多维表格、文本/图片/视频生成、媒体审阅、本地批量保存、ComfyUI 与 Agent Action 放在同一桌面工程中。常见任务是一行代表一个商品、角色或镜头，通过字段引用批量生成和整理结果。

v2.8.2 的核心变化
智能裁切由“只看骨骼关键点”升级为 PoseLandmarker 姿态 + ImageSegmenter 人物语义轮廓。头像能保护真实发顶；服装裁切能读取衣物横向轮廓；Agent 可在不修改共享预设的情况下传入一次性参数；短裙预设可在常用比例中选择更合适的近似比例。
选择图片单元格→本地识别姿态与轮廓→按预设求解裁切框→写入 cropData→预览或人工微调

2. 安装、升级与启动

2.1 首次接收分享文件夹

  1. 将文件夹解压到路径较短、可写入的位置。
  2. 安装 Node.js 后在项目目录运行 npm ci；分享包不重复携带 node_modules。
  3. 运行 npm run dev 启动 Vite 与 Electron。
  4. 若使用音视频裁切，把团队统一维护的 FFmpeg 运行库放到 ffmpeg/bin；代码升级包不重复携带 exe。

2.2 从旧版本升级

先保存当前 .aistudio.json 工程，再覆盖代码并重新执行 npm ci。v2.8.2 不要求迁移旧表格；旧的裁切数据仍可继续预览与生成。

首次使用智能裁切需要联网下载姿态模型、轮廓模型和 MediaPipe WASM。成功后由 Electron/Chromium HTTP Cache 复用；清理应用缓存后会重新下载。

3. 工程、项目与表格

  • 工程：完整的 .aistudio.json 工作文件，可包含多个项目文件夹和子表。
  • 项目文件夹：用于整理子表，可创建、重命名、排序、折叠和拖入/拖出；删除项目只解除归属，不删除子表数据。
  • 子表：保存字段、记录、AI 配置与媒体数据。CSV 只适合单表交换，完整项目结构请使用 JSON。

工程标题会显示“项目名 › 子表名”。建议先建立模板子表，再复制到不同渠道或批次，减少重复配置。

4. 字段与 AI 工作流

字段典型用途注意事项
文本 / 数字 / 标签货号、提示词、规格、状态字段引用使用 {字段名}
附件 / 图片参考图、生成结果、视频和音频一格可有多项媒体
智能文本标题、描述、视觉分析可引用同一行其他字段
智能图片文生图、图生图、LoRA、局部修图模型字段引用时只透传目标模型支持的参数
智能视频首尾帧、参考视频、音频驱动不同模型会筛选无效参数

批量运行前先测试 1～5 行。Qwen 人物 LoRA 使用注册的 Profile ID；默认提示词由工作流前置，表格文本作为追加内容。普通位图输出统一按 PNG 处理，TT Image 2.6 的 SVG/GIF 属于其专用能力。

5. 图片与媒体操作

图片单元格支持预览、评分、打点批注、Photoshop 打开、复制/剪切、批量打包与裁切。单独复制一个素材时不继承图片 cropData，评分与批注保留；以单元格为单位复制或剪切时保留完整属性。

智能裁切写入的是既有 cropData，因此不会制造第二套互不兼容的裁切格式。双击图片仍可在原裁切界面中人工调整，右键“清除所选裁切”仅删除裁切数据，不会清除评分或批注。

6. 智能裁切操作

  1. 在图片或 AI 图片列选择一个单元格、连续区域或多个单元格。
  2. 右键，在“批量打包/导出附件”下方进入“智能裁切”二级菜单。
  3. 选择预设，观察右下角识别、计算和写入进度。
  4. 完成后打开图片预览裁切结果；不满意可人工微调或清除所选裁切。

7. 识别技术与裁切逻辑

7.1 两个模型各自负责什么

技术提供的数据在裁切中的作用
PoseLandmarker Full眼、耳、鼻、肩、胯、膝、脚踝等关键点确定人物、身体方向与纵向身体区段
ImageSegmenter背景、头发、脸、皮肤、服装和配饰的分类轮廓保护真实发顶与服装横向边缘

7.2 头像为什么不再只靠骨骼估算

关键点只知道脸和关节位置，不知道头发最高像素。v2.8.2 先把轮廓匹配到对应人物，再以 hair 的最高、最左、最右像素建立头部硬边界；面部、颈部和肩点只负责位置与下方语境。衣服和手臂不会扩大头部包围盒。

求解顺序是：完整头发与面部必须保留 → 尽量满足理想顶部留白 → 保留所需肩部语境。原图空间不足时先缩减肩部，再把顶部留白从理想值收紧到最低安全线，不以裁断头发换取更多身体。

7.3 服装轮廓如何参与

腰、胯、膝等关键点负责限定纵向范围；该范围内的 clothes 语义行区间负责服装最左、最右边界。这样宽摆短裙和蓬松上衣不会被肩宽或胯宽的骨骼走廊截断。轮廓不可用时退回人物轮廓与骨骼方案。

7.4 固定比例与近似比例

  • fixed：严格保持指定比例，适合换脸、商品模板和统一渠道规格。
  • approximate：在候选比例中先检查必保区是否完整和是否越界，再比较轮廓形状与首选比例；同一批图片可以得到不同结果比例。

8. 裁切参数与手动配置

右键菜单与 Agent 共用 public/smart_crop/presets.json。常规维护只修改这个文件；预设 ID 一旦用于自动化任务，应保持稳定。

8.1 头像参数

参数用途调大后的效果
topMargin理想发顶留白，相对结构头部高度头顶更松，画面更有呼吸感
minTopMargin空间不足时仍保留的最低顶部安全线，相对最终裁切高度更不贴发顶，但更容易压缩肩部或无法求解
sideMargin头发左右留白，相对头部宽度左右更宽松
shoulderDepth颈肩以下希望保留的深度保留更多胸肩；过大时头像显得不够紧
{
  "id": "face_swap_1_1",
  "aspect": "1:1",
  "strategy": "tight_headshot",
  "headshot": {
    "topMargin": 0.14,
    "minTopMargin": 0.06,
    "sideMargin": 0.15,
    "shoulderDepth": 0.20
  }
}

8.2 通用人体参数

参数作用
framing.start / end希望画面覆盖的起止身体部位，是构图目标。
protection.start / end必须保留的身体区间，优先级高于构图目标。
protection.handsnone 不要求手；prefer_one 尽量保留一只；require 类会成为硬约束。
spacing上右下左留白，可用百分比或像素。
aspectModefixed 或 approximate。
aspectCandidates近似模式允许比较的比例列表，常用为 1:1、3:4、4:3、9:16、16:9。
allow_virtual是否允许超出原图；当前内置预设统一为 false，不自动扩图。
参数应从小幅调整开始，并使用多种姿势和画幅验证。提高硬保护与留白会减少可用解；不要把一次特殊图片的补丁直接固化到所有预设。

9. Agent 临时参数

Agent 先调用 media.list_crop_presets 获取共享预设，再用 media.smart_crop_preview 预览。确认后以完全相同的 overrides 调用 media.smart_crop_apply。临时参数不会修改菜单预设。

{
  "version": "0.1",
  "action": "media.smart_crop_preview",
  "params": {
    "tableId": "table_xxx",
    "presetId": "face_swap_1_1",
    "overrides": {
      "aspect": "3:4",
      "headshot": {
        "topMargin": 0.18,
        "minTopMargin": 0.06,
        "sideMargin": 0.12,
        "shoulderDepth": 0.60
      }
    },
    "targets": [
      {"rowId":"row_1","fieldId":"field_images","index":0}
    ]
  }
}

通用人体预设可临时覆盖 aspect、aspectMode、aspectCandidates、framing、protection、spacing。Schema 会拒绝模型地址、内部 cropData、未知字段和超范围数字。返回的 effectiveAspect 是每张图片实际采用的比例。

10. 模型、缓存与隐私

  • 姿态、轮廓与求解都在本机完成，图片不会因智能裁切上传。
  • 姿态与轮廓结果按本地路径、文件大小和修改时间分别写入 IndexedDB；切换预设会复用识别结果。
  • 模型和 WASM 通过 HTTPS 下载并使用 Chromium 普通 HTTP Cache，不放入分享工程。
  • 姿态模型校验文件大小与 SHA-256；轮廓模型执行合理大小校验。
  • 模型或分割失败时自动退回关键点方案；缓存失效时重新识别。

11. 常见问题

一直显示“正在识别人像”

先确认首次下载可访问；再检查 Electron 终端与开发者工具错误。不要反复点击同一任务。清理 HTTP Cache 会触发重新下载。

提示缺少身体参照

图片可能没有拍到预设需要的胯、膝或脚踝。改用较短景别预设，或通过 Agent 临时缩短 framing.end / protection.end。

发顶过紧或肩部太多

发顶过紧可小幅提高 topMargin 或 minTopMargin；肩部太多可降低 shoulderDepth。最低安全线过高会降低受限画幅的可解性。

短裙被截断

确认使用近似比例短裙预设且轮廓模型正常；查看实际 effectiveAspect。若姿势或遮挡导致轮廓分类混淆，先预览其他候选比例，再人工微调，不建议用全局补丁处理单张异常图。

清除裁切为什么没有出现

“清除所选裁切”只在选择区域中存在 cropData 时显示；它与“清除全部标注”是不同操作。
