# AI Table Studio v2.6.8：缩略图按需加载与测量

日期：2026-09-05。产品 2.6.8；API v0.1 / phase4.7；Definition 1.2；85 个 Action。启动脚本保持此前本地配置。

## 已实施（阶段 1）

- ThumbnailImage 的图片、视频及音频封面入口统一采用 IntersectionObserver，rootMargin=120px，threshold=0.01。图片不再在组件挂载时立即发起缩略图 IPC；音频封面通过容器 ref 参与观察。
- 渲染端原生请求队列最大并发 3：同路径及尺寸正在进行的请求共享 Promise；排队后没有可见订阅者则跳过；离开并重新进入时重新尝试。组件卸载解除观察，旧异步结果不写新组件状态。已提交系统服务的请求不能强行取消，仍占槽直到完成，避免假超时释放导致真实并发超限。
- 主进程也复用同一个队列实现约束原生请求，覆盖其他调用点及多个窗口，包含手动刷新；同源请求进行中合并，成功后仍由已有 Renderer Map 缓存结果。文件存在检查由 existsSync 改为异步 access，减少网络元数据检查阻塞主进程。
- 手动刷新带 fresh 标记，使用独立任务，不复用可能过时的进行中结果；仍为系统 150×150 尺寸框，等比例。保持原有修订号保护。
- 原生图片缩略图不可用时不自动加载 NAS 原图，保留占位；手动打开原图的链路保持。视频 fallback 仍使用原有视频队列。网络图／浏览器图在进入视口后沿原有路径加载。
- 不包含持久磁盘缩略图缓存、列虚拟化或审阅卡片虚拟化。没有改动 NAS 图片、Crop、Trim、评分或生成工作流。

## 阶段 0：已执行测量与未完成部分

只读查询当前工程的大表图片引用，确认包含公司 NAS 主机 ds1019plus。当前电脑 DNS 解析失败；开放网络权限后再次解析仍失败，未尝试批量读取不可达文件。因此 **真实 NAS 与本地 SSD 同批文件对照尚未完成，不能给出 NAS 提速百分比或 NAS 瓶颈占比**。

本机使用独立 Electron 进程、30 张 1600×1000 合成 PNG、原生系统缩略图服务测量：

| 测量 | 成功 | 总耗时 | 单次 p50 | 单次 p95 | 并发峰值 |
| --- | --- | --- | --- | --- | --- |
| 本地首次 pass | 30/30 | 336.9ms | 26.3ms | 92.6ms | 3 |
| 同批重复 pass | 30/30 | 250.6ms | 24.3ms | 31.8ms | 3 |

这是本机合成图链路验证，不是用户素材、不是优化前后对照；未清空 Windows 缩略图或 SMB 缓存，首次 pass 不代表严格冷缓存。首轮独立 Electron GPU 初始化失败，使用 `--disable-gpu --disable-software-rasterizer --in-process-gpu` 后测量成功。没有重启或关闭用户工程。

受控请求测试：100 个请求对应 10 个路径，只执行 10 次工作，合并 90 次，峰值并发 3。实际 ThumbnailImage 代码的隔离测试验证未入视口零请求、排队后移出视口跳过、重新进入加载、卸载不再加载。此测试验证行为而非真实 NAS 网络性能。

### 回到公司后的复测

创建 `paths.json`：1–100 个绝对图片路径组成的 JSON 数组。例如 `["\\\\nas\\share\\a.jpg"]`。优先使用 PNG/JPEG 等常见图片；脚本只读原文件，并在本机临时目录复制同批样本作比较。公司允许本地样本副本后再执行。

```bat
npm run benchmark:thumbnails -- --manifest=paths.json --output=thumbnail-report.json
```

不传 manifest 则生成本地合成图用于检查脚本。报告包含 source-first-pass、source-repeat、local-copy-first-pass、local-copy-repeat 的总耗时、成功失败数、并发峰值及 p50/p95；没有请求或计时数据冒充 NAS 结果。

临时副本和报告目录在输出的 scratch 字段，可按公司规范清理；脚本不自动删除素材，也不上传样本。首次运行与重复运行须保持窗口/网络条件一致；若要严格冷缓存实验，需要单独设计，不在脚本中清除系统缓存。

### 运行时统计

新增只读 preload `electronAPI.getThumbnailLoadStats()`，返回主进程原生请求的 requested、started、deduplicated、skipped、failed、peak、active、queued、p50Ms、p95Ms 等累计指标；延迟采样最多保留最近 1000 次，不保存路径或图片内容。Renderer 的 thumbnailLoadStats 导出可供开发诊断。failed 仅表示抛出的队列错误，图片不存在等 null 结果由基准脚本 succeeded/failed 统计，不要将队列 failed=0 理解为所有图片成功。
