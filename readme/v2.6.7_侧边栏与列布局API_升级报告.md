# AI Table Studio v2.6.7 升级报告

日期：2026-09-05。产品 2.6.7；Action API v0.1 / phase4.7；Action Definition 1.2。本版不调整在线／Electron 启动方式。

## 实施内容

1. 侧边栏子表标题添加完整 title 提示；工程名称同样可悬停查看全文。
2. 子表操作按钮非悬停时宽度归零并裁切，悬停或键盘聚焦进入时恢复宽度，文字自动让位。工程名旁编辑图标也释放非悬停空间。
3. 移除插行后整条通知栏及其冗余通知状态。真实锚点插行、筛选预填和分组继承保持；不匹配筛选的新行仍在当前会话暂留，修改筛选、关闭再开启筛选、切换视图或表格后恢复严格筛选。移除通知栏后不再提供栏内的“重新应用筛选”按钮。
4. 移除 PS 打开中／打开结果通知；启动命令失败仅记入控制台，避免文件已经打开却提示失败。缺少 Photoshop 路径或运行环境时仍保留必要配置提示。缩略图刷新自己的结果提示保持。根因核查：main.js 的 exec 回调依据进程退出结果返回布尔值，不能直接当成 Photoshop 文档打开状态。
5. 增加三个表级列布局 Action，直接写 UI 现有属性，不另建一套视图数据：
   - `field.set_hidden`：tableId、fieldIds、hidden；支持批量隐藏／显示。
   - `field.freeze_to`：tableId、fieldId；null 取消连续冻结。
   - `field.set_individual_frozen`：tableId、fieldIds、frozen；独立于连续冻结。

所有 Action 使用明确状态而非 toggle，复用 write:data、dryRun、revision、幂等及 Undo 路径。table.get_schema 增加 columnLayout 读回。HTTP Schema 从 Definition 生成，CLI 自动获得帮助和校验。冻结范围按 UI 的可见字段计算；隐藏连续冻结的端点会暂时使该范围冻结失效，恢复显示后恢复，和手工 UI 行为一致。

## NAS 大表缩略图：评估与后续方案（本版不实施）

场景：400+ 行、40+ 列、1000–3000 个图片附件。结论：工程端有确定的优化空间，当前证据不足以把慢完全归因于 NAS，也不能量化 NAS 占比。

### 当前实现证据

- Grid 已有行虚拟化，overscan=5，因此普通表格不是一次绘制全部 400 行。
- 横向仍遍历 visibleFields：滚动区域外的列仍可能创建附件组件。
- ThumbnailImage 的图片分支挂载后立即调用 getOrGenerateThumbnail；IntersectionObserver 实际只用于视频分支。img 的 loading=lazy 延迟显示加载，无法阻止前面已经发出的本地缩略图 IPC。
- 原生 getThumbnail 路径在缩略图队列之前直接请求；现有 MAX_CONCURRENT_THUMBNAILS=5 主要约束后续视频 Canvas 分支，并未给全部图片的原生缩略图请求限流。
- thumbnailCache 是按路径缓存的内存 Map，没有应用自己的持久缩略图缓存，也没有进行中的 Promise 去重；重启后该 Map 清空，同图首次并发请求可能重复。Windows 系统自身是否命中缓存取决于文件及缩略图服务，不能假定每次都读完整原图，也不能假定 NAS 一定命中。
- 审阅视图按分组展开内容渲染卡片，可视刷新按钮虽已限制视口，但这不代表初次加载也被同样限制。
- 原生主进程 handler 对每条路径先做 existsSync；网络盘元数据延迟在大量请求时也可能影响主进程响应。

### 建议执行顺序

| 阶段 | 工作 | 要解决的问题 |
| --- | --- | --- |
| 0：先测量 | 取同一批约 100 张图片，比较 NAS 与本地 SSD 副本；各做冷启动／第二次打开；固定窗口、表格和滚动位置 | 区分网络／磁盘延迟与请求风暴，不用单次主观观感判断 |
| 1：先控请求 | 图片也在进入视口及小幅预加载区时请求；所有原生缩略图统一并发队列，从 2–4 开始实测；按路径和尺寸合并进行中的请求；屏外未开始任务取消或降级 | 首屏优先、减少横向屏外列请求、避免 NAS 被瞬间大量访问 |
| 2：重启复用 | 用户本地磁盘保存系统服务生成的缩略图，缓存键含规范路径、尺寸、mtime、文件大小；异步限流核验变更；缓存设容量上限和 LRU | 重启不必重复生成全部缩略图，同时支持 PS 保存后的失效 |
| 3：必要时再虚拟化 | 测量后若卡片／DOM 仍是瓶颈，再增加审阅卡片虚拟化、横向列虚拟化 | 控制大量卡片与 40+ 列的组件开销，避免先做高侵入重构 |

建议记录：首屏可用时间、首屏缩略图完成时间、原生请求数量及并发峰值、缓存命中率、重复请求数、单请求 p50/p95、UI 主线程阻塞及内存。第一阶段验收应是请求量跟随可视区域，而不是跟随整个附件总量；具体秒数目标要基于测量结果设定。

本地缓存只存缩略图，不搬迁 NAS 原图；必须讨论公司是否允许本机保留缩略图。支持手动强制刷新／清理缓存，NAS 离线时可显示缓存并说明离线状态。路径不变但 PS 已保存时要失效，含 Crop 的显示仍复用原始实例数据，不把裁切／评级写入通用路径缩略图缓存。

优先建议执行阶段 0 + 1；如果重启等待仍明显，再做阶段 2。暂不建议改变图片精度或在 NAS 上为每张图生成旁路文件。
