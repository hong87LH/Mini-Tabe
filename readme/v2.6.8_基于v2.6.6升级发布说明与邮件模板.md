## 一、Git Release 文案

### v2.6.8：侧边栏、列布局 API 与大表缩略图加载优化

本次版本基于 v2.6.6 升级，重点改善侧边栏标题显示、表格交互提示、Agent 列布局控制，以及包含大量 NAS 图片附件时的缩略图加载体验。

### 主要更新

#### 1. 侧边栏与子表标题体验

- 工程名称和子表名称支持悬停查看完整标题。
- 非悬停状态不再为编辑、复制、删除按钮长期预留宽度，标题能够显示更多字符。
- 顶部子表切换菜单的长名称改为单行省略和左对齐，避免换行造成菜单高度混乱。
- 顶部当前子表标题支持双击重命名：Enter 或失焦保存，Escape 取消，空名称不保存。

#### 2. 通知提示精简

- 移除筛选或分组状态下插入行之后的整条通知栏，保留真实位置插入、筛选字段预填和分组字段继承逻辑。
- 移除 Photoshop 打开中、成功及命令执行结果通知，避免文件已经打开却仍出现失败提示。
- Photoshop 路径未配置等需要用户处理的必要提示继续保留。

#### 3. Action API 增加列布局控制

新增 3 个 Action，Action 总数由 82 增加到 85：

- `field.set_hidden`：批量隐藏或显示字段，不删除字段数据。
- `field.freeze_to`：连续冻结至指定字段，传入 `null` 可取消连续冻结。
- `field.set_individual_frozen`：设置一个或多个字段的独立冻结状态。

同时，`table.get_schema` 增加 `columnLayout` 回读。新增操作沿用现有权限、dryRun、confirmed、expectedRevision、幂等和 Undo 机制，不引入第二套列布局状态。

#### 4. 缩略图加载底层优化

- 图片、视频和音频封面统一在进入可视区域或邻近预加载区后再请求缩略图。
- 渲染端和 Electron 主进程均加入缩略图调度队列，主进程实际并发上限为 3。
- 相同路径和尺寸的进行中请求自动合并，减少重复访问 NAS。
- 尚未执行且已经移出可视区域的请求会跳过；重新进入后可以重新加载。
- 组件卸载后不再把旧异步结果写回新界面。
- 主进程的文件存在检查改为异步方式，减少网络文件元数据检查阻塞。
- 增加只读缩略图运行统计，可查看请求数、去重数、跳过数、失败数、并发峰值和 p50/p95 耗时。

#### 5. 可视区域缩略图刷新

- 表格视图右上角、搜索按钮旁新增“刷新可视区域媒体缩略图”按钮。
- 同时按横向和纵向实际可见范围筛选媒体，不刷新屏幕外、折叠或裁切区域。
- 审阅视图和表格视图均复用系统 150×150 缩略图服务。
- 手动刷新使用 fresh 请求，避免复用可能过时的进行中结果。
- 刷新失败时保留旧缩略图，不弹出额外通知，也不会修改附件路径、评分、Crop 或 Trim 数据。

#### 6. 丢失图片显示兼容

- 恢复 v2.6.6/v2.6.7 使用的 Chromium 原生 `<img>` 加载失败视觉样式。
- 表格单元格显示破损图片图标和文件名；图片审阅卡片显示破损图片图标和完整路径。
- 音频继续使用专用占位样式；视频继续使用原有缩略图 fallback。
- 系统缩略图不可用时不会为显示错误状态而重新读取完整 NAS 原图。

#### 7. 测量与开发支持

- 新增缩略图调度回归测试，覆盖视口触发、离屏跳过、重新进入、重复路径合并、并发上限、失败恢复和可视范围判断。
- 新增 Electron 缩略图基准脚本，可使用同批 NAS 图片和本地 SSD 副本进行对照。
- 增加运行时缩略图统计接口，统计数据不保存图片路径或内容。

### 兼容性

- 表格数据结构无需迁移。
- Action API 协议仍为 v0.1，Phase 仍为 phase4.7，Action Definition 仍为 1.2。
- 原有 82 个 Action 保持兼容，仅新增 3 个列布局 Action。
- 本地启动命令、Token 设置和 HTTP 地址保持不变。
- 不修改媒体文件、Crop、Trim、评分、智能字段配置或生成工作流。

### 升级方式

1. 更新代码并确认 `package.json` 版本为 `2.6.8`。
2. 确保新增的 `thumbnail_scheduler.js` 一同进入源代码和 Electron 打包文件列表。
3. 如依赖目录不完整，执行 `npm install`。
4. 完整关闭并重新启动 Electron；仅刷新前端页面不足以加载新的 main/preload 逻辑。
5. 如需启动 Action API，继续使用原命令：

```bat
set "HONGS_TABLE_ACTION_API=1" && set "HONGS_TABLE_ACTION_TOKEN=test-123456" && npm run dev
```

### 验证状态

- v2.6.8 阶段 1记录的 API、HTTP、CLI、Job、插行、审阅及生成策略测试共 95 项通过。
- 后续标题、破图样式和表格可视区域刷新补充完成后，8 项缩略图专项测试通过。
- 生产构建通过。
- 类型检查仍保留升级前已经存在的 `Grid.tsx TS2347`，本版未处理。

### 当前边界与已知事项

- 真实公司 NAS 与本地 SSD 的同批素材对照尚未完成；现有本机合成图测试不能换算为 NAS 提速百分比。
- 本版没有实现应用级持久缩略图磁盘缓存。
- 本版没有实现横向列虚拟化或审阅卡片虚拟化。
- Chromium 原生破图图标的具体外观可能随 Electron/Chromium 版本变化。
- 表格可视区域刷新和长名称交互仍建议在真实生产数据窗口中做一次人工验收。

## 二、同事邮件模板

### 邮件主题

AI Table Studio v2.6.8 更新通知：缩略图加载、侧边栏及列布局 API 优化

### 邮件正文

各位好：

AI Table Studio 已由 v2.6.6 更新至 v2.6.8。本次主要改善大表格和 NAS 图片附件场景下的缩略图加载体验，同时补充了侧边栏标题交互和 Agent 列布局控制。

主要变化如下：

1. 工程名和子表名支持悬停查看完整标题，顶部子表菜单长名称改为单行省略；顶部标题可双击重命名。
2. 精简筛选/分组插行及 Photoshop 打开过程中的非必要通知。
3. Action API 新增隐藏列、连续冻结列和单独冻结列能力，Action 数量由 82 增加到 85。
4. 图片、视频和音频封面改为按可视区域加载；增加并发限制、重复请求合并和离屏任务跳过，降低打开大表时对 NAS 的瞬时访问压力。
5. 表格右上角新增“刷新可视区域缩略图”按钮，审阅视图和表格视图都继续使用系统 150×150 缩略图。
6. 图片路径失效时恢复原来的破损图片图标及文件名/完整路径显示方式。

本次升级不需要迁移表格数据，Action API 的地址、Token 配置和启动方式均不变。更新后请完整关闭并重新启动 Electron，以加载新的主进程和 preload 代码。

当前版本已通过自动测试和生产构建。真实公司 NAS 的定量速度对照仍待网络环境可用后补测，因此目前不对具体提速比例作承诺。

如发现以下问题，请记录表格名称、视图模式、可见行列范围、媒体类型及文件路径类型后反馈：

- 可视区域内缩略图没有开始加载；
- 刷新按钮未更新刚刚在 Photoshop 中保存的图片；
- 丢失文件没有显示破图图标或路径文字；
- 隐藏列或冻结列 Action 与 UI 状态不一致。

谢谢。
