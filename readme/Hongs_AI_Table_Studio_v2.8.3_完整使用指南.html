      1. 工具是什么#

      Hong's AI Table Studio 是一款把“多维表格、AI 内容生成、本地素材管理和后台任务”组合到一起的桌面工作站。它可以像飞书多维表格、Airtable 或 Excel 一样管理逐行数据，同时让每一行调用 AI 生成文本、图片或视频。

      典型用途包括：

      • 按货号、颜色、渠道管理商品视觉任务；
      • 通过表格批量生成标题、卖点、提示词和描述文案；
      • 一行放多张参考图，再批量调用 AI 生图；
      • 用首帧、尾帧、参考图片、参考视频或独立音频生成视频；
      • 通过灵悟等远程 Provider 生成媒体；
      • 通过本机 ComfyUI 直接运行 MiniMax H3 工作流；
      • 通过本机 ComfyUI 运行 Qwen Image 2.1 文生图/多参考图生图及透明 PNG；
      • 对图片打分、打点批注、记录修改意见；
      • 将生成结果按货号、颜色、渠道自动命名并保存；
      • 将远程模型需要的本地参考图上传到阿里云 OSS；
      • 在后台任务中心恢复轮询、断点下载、跳转和写回；
      • 查看 OSS 当前 Bucket 容量和本月公网流量。

      1.1 推荐使用方式#

      日常工作建议使用 Electron 桌面模式。浏览器模式适合看表格和测试部分纯前端能力，但无法完整替代桌面端。

      普通表格编辑 支持 支持
      文本 API 调用 支持 支持，但可能受跨域限制

      灵悟图片 / 视频 支持 不完整

      后台 Job、持久轮询和断点下载 支持 不完整

      2. 使用前先理解五个概念#

      2.1 工程#

      工程是一整份工作文件，扩展名通常为：

      TEXT
      .aistudio.json

      一个工程可以包含多张表。

      2.2 表格#

      表格相当于工作簿中的一个工作表。例如：

      • 主任务表
      • 提示词表
      • 生图结果表
      • 视频任务表
      • 审核记录表

      2.3 字段#

      字段就是“列”。例如：

      • 货号
      • 颜色
      • 参考图片
      • 提示词
      • 智能图片
      • 评分

      每个字段都有固定类型，字段类型决定这一列可以输入什么内容、如何显示、是否能调用 AI。

      2.4 记录#

      记录就是“行”。通常一行代表一个任务、一个货号、一个颜色或一个镜头。

      2.5 引用字段#

      AI 提示词中可以用大括号引用同一行其他字段：

      TEXT
      为货号 {货号} 的 {颜色} 产品生成一张电商主图，场景为 {场景要求}。

      运行到某一行时，系统会自动把 {货号}、{颜色}、{场景要求} 替换成该行的真实内容。

      字段名称必须与大括号中的名称完全一致。重命名字段后，要同步修改所有公式和 AI 提示词中的引用。

      • 写回原单元格；
      • 继续轮询；
      • 重试下载；
      • 查看远程结果；
      • 打开本地文件；
      • 删除任务记录。

      这样即使网络中断、下载失败或软件重启，也知道去哪里继续处理。

      v2.7.6 中，展开侧栏时项目文件夹可展开/收起；折叠侧栏时先显示项目文件夹按钮，进入项目后只显示该项目的子表。灰色文件夹配返回角标的按钮用于返回根目录。侧栏滚动条在需要时悬停显示，避免项目/子表较多时无法继续访问。

      Bucket 默认不会出现在所有卡片上。只有任务属于历史 Bucket，或发生 OSS、参考图上传错误时，卡片才会显示 Bucket 提示。

      5.7 Provider 启用状态与“眼睛”开关#

      每张 API Provider 卡片都有启用/停用状态。

      当多个 Provider 配置了相同模型名时，v2.5.5 不再静默取第一组。正确规则是：

      TEXT
      同一模型
→ 只能有一个匹配 Provider 处于启用状态
→ AI 字段模型名保持不变
→ 通过 Provider 的眼睛切换实际协议

      启用某个 Provider 时，系统会自动停用同类别中与它存在同名模型的其他 Provider。

      如果同一模型没有任何启用 Provider，或同时匹配多个启用 Provider，系统会明确报错，不会自动猜测。

      6. 工程与表格管理#

      6.1 新建工程#

      点击“新建工程”会创建一份新的空白项目。新建前务必先保存当前工程。

      6.2 打开工程#

      点击“打开工程”，选择 .aistudio.json 文件。

      工具会记录最近打开过的工程。若浏览器或系统权限发生变化，最近记录中的文件可能需要重新授权。

      6.3 修改工程名称#

      展开左侧栏，点击工程名称进行修改。

      注意：界面中的工程名称与磁盘上的文件名不是完全同一概念。修改界面名称后，建议再执行一次“另存为”，让文件名保持一致。

      6.4 新增表格#

      在左侧栏点击添加表格按钮。新表会生成默认字段和空记录。

      6.5 重命名表格#

      双击表格名称，输入新名称后按 Enter 保存，按 Esc 取消。

      6.6 复制表格#

      复制表格会复制其：

      • 字段结构；
      • 字段设置；
      • 现有记录；
      • AI 字段配置。

      适合从模板快速创建新渠道、新批次或新项目表。

      6.7 删除表格#

      删除后无法通过普通方式恢复，因此先保存工程或导出 JSON。系统不允许删除最后一张表。

      6.8 调整表格顺序#

      按住左侧栏中的表格条目拖动，即可更改顺序。

      6.9 项目文件夹是什么#

      v2.7.6 的“项目文件夹”用于整理子表，不是第二层工程文件，也不是磁盘目录。当前只支持一层目录：

      TEXT
      工程
├─ 项目 A
│  ├─ 子表 1
│  └─ 子表 2
├─ 项目 B
│  └─ 子表 3
└─ 根目录子表

      字段、记录、AI 配置、附件和 Job 的语义仍属于原来的子表；移动子表到项目只是改变导航归属。

      6.10 创建、重命名与解散项目#

      在左侧栏创建项目后输入名称即可。项目支持重命名和展开/收起。

      解散项目不会删除里面的子表。项目文件夹被删除后，原子表会移回根目录；该操作进入现有 Undo/Redo 机制，可按正常撤销流程处理。

      6.11 把子表移入项目或移回根目录#

      有两种主要方式：

      1. 直接拖拽子表到项目文件夹；
      2. 右键子表，在菜单中选择“移入已有项目”“移回根目录”或“新建项目并移入”。

      项目内也可以直接新建子表。把子表拖出项目时，界面使用临时插入线提示目标位置，不会留下永久占位项。

      6.12 项目与子表排序#

      项目文件夹本身可以拖拽排序；项目内子表和根目录子表也可以各自调整顺序。跨项目移动时，子表会进入目标项目并按目标位置重新排列。

      6.13 折叠侧栏与标题导航#

      侧栏折叠时：

      • 根目录显示项目文件夹与根目录子表；
      • 点击项目文件夹后，侧栏切换为该项目的子表；
      • 点击带返回角标的灰色文件夹按钮回到根目录。

      顶部标题使用“项目名 › 子表名”表达当前位置；标题菜单可以不展开左侧栏就快速切换项目和子表。

      6.14 与旧工程的兼容#

      项目文件夹是可选导航元数据。没有项目文件夹信息的旧工程会像过去一样打开，全部表格位于根目录。v2.7.6 不要求迁移字段或记录。

      7. 字段类型说明#

      点击字段标题左侧的类型图标，可打开字段设置。双击字段名可以重命名。

      字段类型 用途 示例
      文本 普通文字、多行说明 货号、需求、提示词
      数字 数量、价格、尺寸 4、99.9、1080
      单选标签 一条记录只能选一个选项 待处理、进行中、完成
      多选标签 一条记录可选多个选项 天猫、京东、唯品会
      日期 日期记录 2026-07-14
      复选框 是/否状态 是否加声音
      人员 负责人或审核人 张三、李四
      链接 网页地址或媒体地址 产品页 URL
      附件 图片、视频等素材 产品图、首帧图
      公式 根据当前行其他字段计算 {单价} * {数量}
      评分 0～5 星评价 图片质量评分
      智能文本 调用 AI 生成文字 标题、卖点、翻译

      智能视频 调用 AI 生成视频 图生视频、视频扩展

      7.1 文本字段#

      适合货号、颜色、要求、说明和长提示词。编辑时：

      • Enter：保存并移动到下一行；
      • Alt + Enter：在单元格内换行；
      • Esc：退出编辑。

      7.2 数字字段#

      输入内容会转换为数字。粘贴无法转换的文字时可能变为空值或异常值，建议先清洗数据。

      7.3 单选与多选字段#

      可在字段设置中管理选项、名称和颜色。粘贴外部文本时，系统会尽量按选项名称匹配。

      7.3.1 标签字段轻量清理#

      v2.5.5 增加了单选/多选字段的往返清理规则。

      当历史字段中存在已经删除的标签 ID、重复标签或选项表残留时，可以：

      TEXT
      标签字段 → 转为文本 → 再转回单选/多选

      处理逻辑：

      1. 标签转文本时，只保留当前字段选项表中仍然有效的标签；
      2. 无效或已删除 ID 不会再被当成普通文字保留；
      3. 文本转标签支持英文/中文逗号、英文/中文分号和换行；
      4. 自动去空、去重；
      5. 同名有效选项继续复用原来的 ID 和颜色；
      6. 没有被当前文本引用的旧选项会被清理。

      这是清理历史标签数据时最轻量的方案，不需要单独跑迁移脚本。

      7.4 附件字段#

      可加入多张图片或多个媒体文件。新加入的附件会追加到现有内容，不会自动覆盖原附件。

      常用操作：

      • 点击单元格上传；
      • 将文件拖入单元格；
      • 拖动附件调整顺序；
      • 删除、复制或下载单个附件；
      • 点击缩略图进入大图预览。

      当前版本附件字段支持图片、视频和常见音频文件。音频既可以通过文件选择加入，也可以直接拖入附件单元格。

      7.5 公式字段#

      公式通过字段名引用当前行数据：

      TEXT
      {单价} * {数量}

      也可以使用等号开头的表达式：

      TEXT
      ={总额} - {优惠}

      字符串拼接可使用：

      TEXT
      ={货号} & "_" & {颜色}

      当前引擎会将 & 转换为字符串加号处理。

      注意事项：

      • 公式字段主要用于显示计算结果，不建议手动输入；
      • 字段重命名后，公式不会自动更新；
      • 尽量使用简单数字和字符串表达式；
      • 不要把未知脚本或不可信表达式粘贴到公式中。

      7.6 评分字段#

      用于图片筛选、审阅和批量下载。可设置 1～5 星；未评分视为 0 星。

      8. 基础录入与表格操作#

      8.1 新增记录#

      点击工具栏中的“添加记录”，或在已有记录下方继续添加。

      8.2 编辑单元格#

      • 单击：选中；
      • 双击或按 Enter：进入编辑；
      • Esc：退出编辑；
      • Delete / Backspace：清空选中单元格。

      8.3 连续选择区域#

      从一个单元格拖动到另一个单元格，可选择矩形范围。

      按住：

      • Shift：扩展连续选择；
      • Ctrl / Command：追加非连续单元格选择。

      8.4 复制、剪切与粘贴#

      支持类似 Excel 的矩形复制粘贴：

      • Ctrl + C：复制；
      • Ctrl + X：剪切；
      • Ctrl + V：粘贴。

      从 Excel 或 CSV 软件复制的数据，以制表符和换行识别行列。若粘贴内容超过现有行数，系统可自动增加记录。

      附件、智能图片和智能视频字段在粘贴 URL 时采用追加方式。

      v2.7.1 进一步修复附件及 AI 图片等媒体实例的复制/剪切/粘贴：不仅保留文件 URL，还会按对应行为保留评分、批注、裁切（Crop）和音视频时间裁切（Trim）等实例属性；具体复制/剪切的适用范围应以所选单元格和当前来源为准，不要只验证缩略图看起来相同。

      8.5 删除记录#

      选中一行或多行后右键，选择“删除 N 行”。

      8.6 插入记录#

      右键记录区域，可以在选中行上方或下方插入指定数量的记录。v2.6.6 修复筛选、排序、分组场景下的插行定位：操作以选中记录的真实位置与视图语义为准，不应简单把可见列表索引当作底层行索引。

      8.7 调整列宽#

      将鼠标移动到列标题右边缘，拖动即可调整宽度。

      8.8 调整列顺序#

      按住列标题拖动，可调整字段顺序。选中整列范围后，还可以一次拖动多列。

      8.9 冻结列#

      字段菜单中提供：

      • 冻结至此列；
      • 单独冻结此列；
      • 取消冻结。

      “冻结至此列”会固定从第一列到当前列；“单独冻结”只固定指定字段。

      8.10 隐藏字段#

      在字段菜单选择“隐藏字段”，或通过顶部“隐藏字段”面板统一管理。

      隐藏只影响显示，不会删除数据。

      8.11 复制字段与字段属性#

      字段菜单支持：

      • 复制字段：创建一列完整副本；
      • 复制字段属性：只复制字段类型和配置；
      • 粘贴字段属性：将已复制的配置应用到另一字段。

      在批量建立相似 AI 字段时非常实用。

      9. 筛选、分组、排序与搜索#

      9.1 筛选#

      • 等于；

      9.2 分组#

      9.3 排序#

      1. 先按状态排序；

      9.4 搜索#

      点击搜索按钮，或按：

      TEXT
      Ctrl + F

      • 紧凑；
      • 中等；
      • 宽松；

      10. 数据导入、导出、保存与备份#

      这是最容易混淆的部分。当前版本有工程文件、CSV、浏览器缓存、自动备份和后台 Job 记录几套不同机制。

      10.1 五种数据机制的区别#

      机制 保存内容 主要用途
      工程文件 .aistudio.json 多张表、字段、记录、AI 字段配置 完整继续工作
      CSV 当前表格的扁平数据 Excel 交换、运营交付
      浏览器本地缓存 最近编辑状态和本机偏好 临时恢复，不应作为唯一备份
      .backup 自动备份 当前工程数据副本 防止误关、崩溃或覆盖
      network-jobs.json 后台任务阶段、task_id、结果地址和写回位置 恢复长时间运行的图片、视频任务

      10.2 保存工程#

      使用“保存”或快捷键：

      TEXT
      Ctrl + S

      第一次保存时需要选择文件位置。之后“保存”会尝试写回原文件。

      10.3 另存为#

      用于：

      • 创建版本副本；
      • 更改文件名；
      • 保存到其他目录；
      • 开始新批次前保留旧版本。

      推荐命名：

      TEXT
      项目名_日期_版本.aistudio.json

      示例：

      TEXT
      秋冬家居服主图_20260802_v03.aistudio.json

      10.4 导入 JSON#

      支持两类 JSON：

      1. 完整工程；
      2. 单张表结构。

      拖入 JSON 时，系统可能询问是替换当前工程还是追加到当前工程。替换前先保存。

      v2.7.6 仍保持旧的“顶层子表数组”结构，不把工程改成新的嵌套 JSON。项目目录信息以可选字段保存：

      TEXT
      首张表：projectFolders（可选）
各子表：projectId（可选）

      “替换”导入会恢复项目目录和归属；“追加”导入会为追加内容重建必要的 ID 与项目映射，避免与当前工程冲突。旧工程没有这些字段时继续按根目录表格处理。

      10.5 导入 CSV#

      导入 CSV 后，所有列默认按文本字段创建。需要数字、附件、AI 或标签类型时，应在导入后手动修改字段类型。

      建议 CSV 使用 UTF-8 编码，避免中文乱码。

      10.6 导出 JSON#

      导出 JSON 可作为完整工程备份或跨设备转移文件。

      如果工程使用了项目文件夹，v2.7.6 导出的 JSON 会同时保留 projectFolders / projectId 导航信息。不要把使用项目文件夹的工程再用旧版本打开并重新保存，旧版本不了解新增目录字段，可能丢失目录归属；升级前后的关键工程建议各保留一份 JSON 备份。

      10.7 导出 CSV#

      CSV 只导出当前表格：

      • 公式字段导出计算后的结果；
      • 附件、智能图片、智能视频导出为逗号分隔的 URL；
      • 单选、多选导出显示名称；
      • 不会保留字段颜色、AI 配置和批注意义结构。

      因此，CSV 不能替代工程文件。

      10.8 自动备份#

      开启前必须先保存工程。开启后系统按设定间隔写入同目录 .backup 文件。

      推荐工作方式：

      TEXT
      工程文件 + 自动备份 + 每日另存版本

      10.9 后台 Job 记录#

      后台任务记录保存在 Electron 用户数据目录中的：

      TEXT
      network-jobs.json

      Job 记录保存任务信息，不保存图片或视频文件本体。

      当前自动整理规则：

      • 已完成且超过 30 天的 Job 会在软件启动时清理；

      • submission_unknown 不会被自动删除；
      • 卡片右上角垃圾桶可以手动删除记录。

      删除 Job 记录不等于取消远端付费任务。运行中的任务删除后，后续结果可能无法自动轮询、下载或写回。

      11.4 同模型 Provider 的眼睛开关#

      从 v2.4.9 起，Provider 卡片右侧可以启用或停用。

      这解决了一个重要问题：同一个模型名可以同时存在于不同协议，但运行时必须明确选择一个。

      例如：

      Provider 格式 模型 状态
      A 灵悟AI Format same-model 关闭
      B OpenAI Format same-model 开启

      AI 字段仍填写：

      TEXT
      same-model

      真正调用 B。

      规则：

      • 旧配置没有 enabled 字段时，默认视为启用；
      • 开启一组 Provider 时，会自动关闭同类别内与它模型名重叠的其他 Provider；
      • 模型下拉候选只汇总当前启用 Provider 中的模型；停用 Provider 的模型不再出现在候选列表；
      • 生成只匹配启用 Provider；
      • 0 个匹配或多个匹配都会明确报错；
      • 不再静默回退到第一组 Provider。

      v2.7.5 同时关闭了模型输入框的浏览器历史自动补全，避免已经删除或停用的旧模型名称被浏览器自身再次提示。已经保存在字段中的旧值不会自动替换；若另一个启用 Provider 仍显式配置该旧名称，它仍会正常进入候选。

      13.10.1 不同图片接口的注意事项（先读）#

      OpenAI Format#

      系统调用 /images/generations，并请求 Base64 结果。若同时传参考图，会附加 base64Array 参数。

      base64Array 不是所有官方或兼容接口都支持的标准字段。若文生图正常、参考图生图报错，需要确认代理服务是否支持该扩展参数。当前兼容请求还包含 model、prompt、n、像素形式的 size 与 response_format: "b64_json"；新增模式/画质参数是否被服务商接受，要按所接接口单独验证。

      Gemini Format#

      普通 Gemini Format 主要用于文本。当前图片工作流不通过这个分支生成图片；建议使用 Gemini Custom、OpenAI 兼容图片接口，或灵悟中的 Gemini 图片模型。不要因为 Provider 和模型都带有 Gemini 字样，就误认为它们共用请求格式。

      Gemini Custom#

      可发送多张内联参考图，适合兼容 Gemini 图像生成的自定义接口。当前 :generateContent 分支用 contents[].parts[] 承载 Prompt 与 Base64 inlineData，图片配置放在 generationConfig；另有 :predict 分支，采用不同的 instances / parameters 请求结构。

      注意：当前 :predict 分支的实际 instances 只组装 Prompt，不能把 :generateContent 的多参考图能力自动理解为两个分支都等效支持。Nano 2 的模式映射在 Gemini Custom 与灵悟中也位于不同的请求层级。

      灵悟AI Format#

      必须在 Electron 桌面端运行。使用本地参考图时通常需要 OSS。灵悟图片任务提交后会进入后台 Job 流程，不需要一直停留在当前单元格等待。

      灵悟接口通过 /v1/media/generate 提交 model / prompt / params / count；图片字段的尺寸、比例、模式、画质都在模型专属 Mapper 中确定后进入 params，不是把统一 UI 的原值全部原样提交。实际参考图走 JPEG 或 WebP 路线由模型参考素材 Profile决定。

      ComfyUI Local（Qwen Image 2.1）#

      本地图片通过 ComfyUI Workflow Registry / Manifest 选择 Qwen 路由。本机素材直接上传 ComfyUI input，不通过 OSS。分辨率、画质和透明图要求写入 ComfyUI 的工作流/节点输入；生成完成后同样进入本地 Job、下载与单元格回填。

      本地 Qwen 和本地 MiniMax H3 属于同级模型路线，共享 ComfyUI 公共基础设施，但图片的 K 系数/采样步数不能套用 H3 视频的 MP/时长参数。参见第 15–17 章。

      13.10.6 详细模型与协议参数#

      A. OpenAI Format：像素 size、Base64 与兼容扩展#

      当前图片请求构造位置在 src/components/Grid.tsx：

      JSON
      {
  "model": "所选模型",
  "prompt": "最终提示词",
  "n": 1,
  "size": "1024x1024",
  "response_format": "b64_json"
}

      如有参考图，额外附加 base64Array；生成结果解析 data[].url 或 data[].b64_json。图片尺寸由前台既有像素表推导，不走灵悟的 Mapper。未登记专属模型控制映射时，客户端可发送已显式设置的模式/画质，但不保证任意官方或中转服务接受。

      B. Gemini Custom：generateContent、predict 与 Nano 2#

      1. Endpoint 没有模型动作时，拼接 /models/{模型名}:generateContent；如果已包含 :generateContent、:predict 或 :generateImages，不重复拼接。
      2. :generateContent 构造 contents[].parts[]，多张参考图用 Base64 inlineData；generationConfig 包含 responseModalities: ["IMAGE"]、imageConfig.aspectRatio 和 numberOfImages: 1。分辨率不是 1K 时才附加 imageConfig.imageSize。
      3. Nano 2 的模式 auto / high → generationConfig.thinkingConfig.thinkingLevel: minimal / high；没有单独的 quality。切勿照搬灵悟的 params.thinkingLevel 路径。
      4. 当前 :predict 另走 instances: [{prompt}] 与 parameters.sampleCount / aspectRatio，现有代码没有将 :generateContent 的 inlineData 拼进 instances，所以该分支多参考图不能直接视为等效支持。
      5. 结果分别从 candidates[].content.parts[].inlineData 或 predictions[].bytesBase64Encoded 解析；不等于灵悟的 OSS + task_id + Job 协议。

      Nano 2 模式高档的结构示意（摘录关键字段，不代表完整请求体）：

      JSON
      {
  "generationConfig": {

      15.3 首次安装和启动#

      v2.7.4 起，同一套工作流不再限定只能从本机 127.0.0.1 调用。若公司局域网另一台机器运行 ComfyUI，可在“本地应用设置 → ComfyUI 服务地址”填写目标 HTTP/HTTPS 地址，再点击“应用”统一更新图片/视频 ComfyUI Provider。

      16.3 H3 清晰度如何换算#

      H3 的 ResolutionSelector 接收的是百万像素。前台的 360P / 480P / 720P / 1080P 表示目标短边。

      换算逻辑：

      TEXT
      目标 MP = 短边² ×（长边比例 ÷ 短边比例）÷ 1,000,000

      常用映射：

      比例 360P 480P 720P 1080P
      1:1 0.1296MP 0.2304MP 0.5184MP 1.1664MP
      2:3 / 3:2 0.1944MP 0.3456MP 0.7776MP 1.7496MP
      3:4 / 4:3 0.1728MP 0.3072MP 0.6912MP 1.5552MP
      9:16 / 16:9 0.2304MP 0.4096MP 0.9216MP 2.0736MP
      21:9 0.3024MP 0.5376MP 1.2096MP 2.7216MP

      ComfyUI 节点还会按模型要求对尺寸做倍数对齐，因此最终像素可能略高或略低于理论值。

      17.4 分辨率不是 H3 的 MP#

      Qwen 中的 0.5/1/1.5/2 是 K 系数，基准边长系数约为 系数×1024；再按目标比例求宽高、按 32 像素对齐。

      TEXT
      r = 宽 / 高
resolution = 系数 × 1024
w ≈ round(resolution × sqrt(r) / 32) × 32
h ≈ round(resolution / sqrt(r) / 32) × 32
      方图档位 理论输出
      0.5K 512×512
      1K 1024×1024
      1.5K 1536×1536
      2K 2048×2048

      图生图参考图同样按照目标面积等比缩放后进入编码器，不走 resolution=0 的原尺寸路径；非方图最长边可以超过对应数字，32 对齐可能导致最终宽高比略偏。2K 大图不意味着永远比 1K 更经济。

      17.5 比例、模式和画质如何分别起作用#

      局部修图是特殊优先级：本节的“普通图生图自动/显式比例”规则只适用于未启用局部修图的任务。开启局部修图后，应以第一张原始图片的 Crop / 实际宽高比为生成比例，详见第 20.2 节。

      比例：文生图接受 UI 的比例或字段引用（如 3:4），auto 默认 1:1；图生图在比例为自动/未填写时按首图原始比例决定结果，在比例为具体值时会创建 EmptyLatentImage 覆盖画布。

      模式：对外 auto/high；内部 standard/enhanced 只是兼容名称。当前 Qwen 两档共用同一 image_api.json 和已安装权重，high 暂不切换别的模型。

      画质：

      UI Qwen KSampler steps
      auto 25
      high 30
      max 40

      工作流采样参数使用 Euler / Simple、CFG 1、denoise 1；与 H3 Fast 的 6 步 Turbo 无关。未来其他权重尚未接入，不要因为 qwen3vl_8b 文本编码器名字就声称整套图像模型一定是 8B 或已经具备 16B 高模式。

      17.6 透明 PNG 模型的边界#

      18. 批量工作流与后台任务中心#

      批量工作流负责从左到右执行 AI 字段；后台任务中心负责管理已经提交、需要长时间排队、轮询、下载和写回的图片或视频任务。

      18.1 工作流执行顺序#

      选中一行或多行，右键：

      TEXT
      运行智能生成（N）

      基本逻辑：

      1. 按选中记录顺序逐行；
      2. 每行从左到右查找 AI 字段；
      3. 跳过已有结果的 AI 单元格；
      4. 跳过没有提示词的 AI 字段；
      5. 文本即时请求按原逻辑处理错误；
      6. 图片/视频付费任务避免上层盲目重复提交；
      7. 当前行无法继续时进入下一行。

      18.2 为什么 AI 字段顺序重要#

      TEXT
      基础信息
→ AI 文案
→ AI 提示词
→ AI 图片
→ AI 视频

      后面的字段引用前面的结果时，依赖字段必须放在左侧。

      18.3 已有结果不会自动覆盖#

      需要重新生成时：

      1. 先确认旧结果是否要保留；
      2. 清空目标 AI 单元格；
      3. 再运行工作流。

      18.4 推荐分批策略#

      建议：

      TEXT
      1 行
→ 3–5 行
→ 确认字段/模型/路径/Job
→ 20–50 行分批

      对于本地 ComfyUI，尤其要注意显存和队列长度；对于远程 Provider，要注意限频和成本。

      18.5 Job 阶段#

      阶段 含义

      TEXT

      18.6 Job 卡片常用操作#

      跳转原单元格#

      切换到任务来源表格并定位原记录/字段。

      虚拟列表支持远距离定位；如果目标被筛选或折叠隐藏，会提示先清除筛选或展开。

      写回原单元格#

      任务已经有本地结果、但单元格没有自动写回时使用。

      写回会：

      • 检查原表格/记录/字段；
      • 使用纯本地路径；
      • 避免重复追加同一个结果。

      继续轮询#

      适合已经有远程 task_id 或 ComfyUI prompt_id 的任务。

      对于 ComfyUI，手动继续轮询会清除旧错误并恢复状态检查。

      重试下载#

      只重新下载/后处理，不重新创建媒体任务。

      删除任务记录#

      只保证删除本地 Job 记录，不等于取消远程或 ComfyUI 队列中的任务。

      18.7 软件重启后的恢复#

      重启后会尽量恢复：

      • polling 且有任务 ID 的任务；
      • 已生成但尚未完成本地下载的任务；
      • 已有 .part 的断点下载；
      • ComfyUI queued / running 状态。

      创建阶段关闭软件、又没有拿到任务 ID 的远程任务可能成为：

      TEXT
      submission_unknown

      这类任务应先查服务商后台，不要立即重提。

      18.8 Job 与单元格路径#

      v2.4.10 后，Job 写回不再保存：

      TEXT
      file://\server\share\...

      而是保存纯本地/UNC 路径：

      TEXT
      \server\share\...

      这样缩略图、复制路径和后续文件工具不会被 file:// 污染。

      18.9 弱网和长队列的正确处理#

      远程 Provider#

      • polling 临时失败：等待自动恢复；
      • generated 下载失败：重试下载；
      • submission_unknown：先查服务商后台；
      • 401/403/400/模型错误：先修配置。

      本地 ComfyUI#

      • queued 很久：检查 ComfyUI 队列，不要重复提交；
      • running 很久：看显存、Console 和工作流进度；
      • ComfyUI 意外退出：配置了 BAT 时会尝试恢复；
      • execution_error：以 ComfyUI 控制台报错为准。

      18.10 v2.7.0 生成占位符与多 Job 回填#

      进行中 Job 的单元格占位不再作为“空路径图片”请求缩略图或进入媒体大图。中尺寸占位显示 “生成任务待回填”，删除占位符不等于取消后台任务。

      19.15 智能裁切与双模型人物轮廓#

      智能裁切怎么使用#

      1. 在图片或智能图片列选中一个单元格、连续区域或多个单元格；
      2. 右键打开菜单，进入“智能裁切”二级菜单，选择换脸头像、长发胸像、上衣、裤子或短裙等预设；
      3. 识别与求解完成后，成功项更新该媒体实例的 cropData，失败项跳过且保留原裁切；
      4. 双击图片仍可进入原裁切界面人工微调；仅当所选媒体存在裁切时，一级菜单显示“清除所选裁切”。

      一个单元格有多张图时默认逐张处理。右键菜单和 Agent 使用同一份 public/smart_crop/presets.json，因此快捷预设和自动化不会出现两套规则。

      姿态与轮廓分别负责什么#

      • PoseLandmarker Full：识别眼、耳、鼻、肩、胯、膝、踝等人体锚点，确定身体纵向范围和人物身份；
      • ImageSegmenter：输出人物、头发、脸、皮肤、服装和配饰等 category mask，补足骨骼无法描述的真实外轮廓；
      • 头像：完整头发和最低顶部安全线是硬约束，肩部深度是可缩减的软语境；空间不足时先减少身体，不以裁断发顶换取肩部；
      • 服装：骨骼负责腰、胯、膝等纵向锚点，语义服装轮廓负责横向保护，宽摆短裙和蓬松上衣不再只按骨架宽度裁；
      • 保底：分割下载、超时或匹配失败时自动退回关键点方案，不阻塞整批任务。

      固定比例、近似比例与参数#

      参数作用调整方向
      aspectModefixed 严格固定；approximate 在候选比例中逐图选择能保护目标轮廓的比例头像/模板用 fixed；服装轮廓变化大时可用 approximate
      topMargin头像理想发顶留白，相对头部高度增大更松，减小更紧
      minTopMargin原图空间不足时仍必须保留的发顶安全线，相对最终裁切高度不建议设为 0
      sideMargin头像左右留白，相对头部宽度增大更松，减小更紧
      shoulderDepth肩线以下保留的身体语境减小可减少胸肩，增大可保留更多上身
      framing期望景别（软约束），可带 startOffset / endOffset固定比例、原图边界或硬保护冲突时允许放宽
      protection最低必保范围（硬约束）与手部策略优先于 framing；这里定义真正不能裁掉的身体区间
      spacing上、右、下、左留白为主体边缘增加呼吸空间

      契约重点：overrides 是叠加到共享预设，不是从空配置开始。只修改 framing.start 时，预设原有的 protection.start 仍然生效。Preview / Apply 会返回 constraintContract，回显最终采用的软景别、硬必保范围、比例和潜在冲突；Agent 必须读取该字段，不能只看自己提交的参数。

      处理当前单元格全部图片的“腰上到脚踝”时，不写 targets[].index，并使用 framing: above_waist→ankle、protection: hip→ankle。这样腰上是希望保留的构图语境，胯到脚踝是最低必保内容；如果腰上也绝不能裁掉，则把 protection.start 同步设为 above_waist。

      坐姿、蜷腿、横卧或关键点误识别时，脚踝沿肩胯身体轴的投影可能落到腰/胯起点之前。此时返回 ANCHOR_ORDER_CONFLICT，失败图片保持原裁切并交由人工复核；这不是比例错误，也不应通过互换 start/end 绕过人体语义。

      姿态与轮廓结果分别缓存在 IndexedDB；同一图片切换预设会复用识别结果。模型与 MediaPipe WASM 使用 Electron/Chromium 普通 HTTP Cache，首次使用需联网，清除应用 HTTP 缓存后会重新下载。更完整的预设字段、Action 示例、模型 URL、缓存和维护入口见工程内《智能裁切与 Agent 批量裁切》。

      局部修图比例的固定优先级（v2.7.2b 起）#

      这是局部修图一直沿用的核心规则：比例参数以第一张原始图片为准，而不是普通图片字段里的比例下拉。

      场景 生效比例 Qwen KSampler latent
      文生图 普通比例参数；自动缺省 1:1 EmptyLatentImage
      普通图生图，自动/不填比例 第一张参考图比例 TextEncodeQwenImage21 原生 latent

      局部修图，第一张原始图有 cropData.ratio 第一张原始图保存的取景框比例，覆盖普通比例设置 EmptyLatentImage
      局部修图，第一张原始图无 Crop 第一张原始图实际宽高比，映射到既有标准画幅 EmptyLatentImage

      只看第一张实际原始图，不会跳到第二张恰好带有 Crop 的图片。若第一张图的比例无法可靠读取，应中止并报错，而不是静默使用错误画幅。

      22.7 流量查询权限#

      容量查询和流量查询不是同一套权限。

      如果容量能查、流量提示：

      TEXT
      NoPermission
403

      通常表示当前 AccessKey 可以访问 OSS，但没有 CloudMonitor 指标读取权限。

      这种情况下：

      • Bucket 容量仍可正常显示；
      • 流量区域无法得到完整数据；
      • 不应把它误判为 OSS 上传整体失效。

      22.8 当前“账号总流量”已知兼容问题#

      当前实现对：

      TEXT
      MeteringInternetTX

      分别查询当前 Bucket 和未指定 Bucket 的账号级结果。

      当前代码对账号级返回只取“最新数据点”。在部分返回结构下，可能得到与当前 Bucket 相同的值，从而出现：

      TEXT
      账号总流量 = 当前 Bucket
其他 Bucket = 0

      即使账号实际还有其他 Bucket，也不能仅凭“其他 Bucket = 0”判断它们没有流量。

      在账号级聚合逻辑进一步修正前：

      • 当前 Bucket 流量可作为主要参考；
      • 账号总量/其他 Bucket 视为辅助信息；
      • 需要精确账号汇总时应以阿里云控制台或后续修正版为准。

      22.9 OSS 常见错误#

      AccessDenied#

      Bucket 权限不足或策略阻止操作。

      NoSuchBucket#

      Bucket、区域或 Endpoint 不匹配。

      Domain 异常#

      检查 Endpoint 是否误填成完整 Bucket 域名。

      上传成功但远程模型读取失败#

      检查对象公网可访问性和服务商是否能读取该 URL。

      容量正常但流量 403#

      CloudMonitor 指标权限不足。

      “其他 Bucket”始终为 0#

      先确认账号是否确有其他 Bucket 流量；当前 v2.5.5 账号级聚合存在兼容边界，不要直接当作真实 0。

      出现历史 Bucket#

      Job 创建时使用的 Bucket 与当前设置不同，常见于切换员工配置或查看旧任务。

      旧版本可以读取原有表格数组，但不了解 v2.7.6 新增的 projectFolders / projectId 导航元数据。若再用旧版本保存，可能丢失项目归属。因此使用目录功能后，建议保留升级前 JSON 备份，并继续用 v2.7.6+ 编辑。

      25.52 智能裁切第一次很慢或超时#

      首次调用需要初始化 Worker，并可能下载姿态模型、分割模型和 WASM；后续同图切换预设会命中 HTTP Cache 与 IndexedDB。请先保持联网并等待一次完整初始化。Agent Runtime 最长等待 60 秒：没有可用窗口返回 RENDERER_UNAVAILABLE，超时返回 RENDERER_TIMEOUT 与 retryAfterMs。写请求状态不明时必须沿用原 idempotencyKey 查询或重试，不能换新 Key。

      25.53 智能裁切跳过或构图不合适#

      先区分两类结果：skipped[] 表示行、字段、媒体、索引等目标解析失败；failed[] 表示目标有效但识别或求解失败。头像先检查头发是否完整，再调整 topMargin / minTopMargin / shoulderDepth；服装先确认纵向锚点，再用近似比例保护宽轮廓。ANCHOR_ORDER_CONFLICT 表示坐姿、蜷腿、横卧或误识别导致身体锚点无法按肩胯轴可靠排序，失败项会保留原裁切并等待人工复核。正式预设修改 public/smart_crop/presets.json，一次性任务使用 Action overrides，不要直接手写内部 cropData。

      28. v2.8.3 已知限制与兼容边界#

      1. 智能裁切首次使用需要联网下载姿态、分割与 WASM 资源；清除 Electron/Chromium HTTP Cache 后会重新下载。识别失败会退回关键点方案，但极端姿势、遮挡和多人重叠仍可能需要人工微调。

      2. 智能裁切的 approximate 会在允许的常见比例中逐图选择，适合保护服装轮廓，但同一批图片最终比例可能不同；需要严格模板一致时必须使用 fixed。

      3. Qwen LoRA 字段只接受 Manifest 已登记的 Profile ID，不允许通过 Agent 任意加载本机文件。新增权重必须同步模型资产台账、HardLink、消费者路径与维护记录。

      4. 引用模式会忽略目标模型不支持的参数；SVG/GIF 的隐藏细项采用模型默认值。若业务需要精确控制 TT Image 2.6 的专用参数，应使用固定模型配置而不是仅靠公共引用面板。

      5. Qwen Image 2.1 当前图片路由最多 5 张参考图，实际可用数量还受显存、图片尺寸与参考内容影响；文生图 0 张图可用。

      6. Qwen 生成模式 high/enhanced 目前只是预留入口，不切换新的 16B 模型或第二套权重；画质档对应 25/30/40 步。

      7. Qwen 图生图在“自动（图生图跟随首图）”模式下输出比例跟随第一张参考图；若明确填写具体比例，则会覆盖画布比例。文生图一直可以设置比例。

      8. Qwen 采样分辨率 0.5–2K，不能直接把 H3 的 0.7 MP 或云端 4K 规则套用；2K 不保证多参生成速度。

      9. Qwen 透明提示包装并非强制后处理抠图；下载路径可保留 PNG 原有 Alpha，但是否真正透明仍取决于模型结果。

      10. TT Image 2.5 与 Nano 2 各有专属参数映射；其它兼容接口即使透传 mode/quality，也不保证服务端识别。

      11. 本地 Qwen 工作流需要另外安装 ComfyUI 核心/模型权重；MiniMax H3 插件规则不适用于 Qwen。

      12. 本地系统缩略图失败不会为占位而重新读整张 NAS 原图；当前没有持久磁盘缩略图缓存或审阅卡片虚拟化，也没有真实 NAS 提速百分比结论。

      13. 生成中 Job 占位符与媒体文件不同；删除本地标记、Job 历史不等于取消远端付费任务。

      14. v2.7.1 复制属性有区分：单独复制缩略图不继承 Crop；整 Cell 复制/剪切继承 Crop/Trim/评分/批注。

      15. Action API 仍是本机 localhost HTTP 协议，不是 MCP Server；默认关闭，普通 npm run dev 不监听 17321。

      16. Agent 不开放 Provider Key、OSS Secret、任意脚本执行；workspace.save 只能保存已绑定且有权限的工程文件。

      17. 工作流及后台代码更新后须完整重启 Electron；Vite 热更新不更新已经载入的 Main/Preload/ComfyUIClient。

      18. OSS 清理会真实删除对象；submission_unknown 需要核对后台避免付费重提。

      19. 项目文件夹当前只支持一层，不支持项目嵌套项目；目录属于导航元数据，不是磁盘文件夹。

      20. 局域网 ComfyUI 需要目标实例主动监听局域网并允许防火墙访问；远程不可达时不会自动回退到本机 BAT。

      21. banana-2.1 当前不会自动启用联网搜索；Nano 系列没有独立 quality 参数。

      22. banana-pro 是当前专属 Pro 映射名；历史 gemini-3-pro-image-preview 不会自动批量迁移。

      23. 审阅大图默认整图只改变查看方式，不删除 Crop；生成仍读取已保存的媒体/裁切数据。

      24. 使用 v2.7.6 项目目录信息后，不建议再用旧版本重新保存同一工程，以免目录归属元数据丢失。

      31.1 API 是什么，不是什么#

      它是当前 Electron 应用内部能力的 localhost Action Bridge：

      TEXT
      外部 Agent
→ HTTP Action
→ Electron Main
→ Renderer Runtime
→ 当前用户正在编辑的真实 Table / Media / Generation / Job

      它不是：

      • 公网服务；
      • 局域网共享 API；
      • MCP Server；
      • 任意 JavaScript / Shell 执行器；
      • Provider / OSS 密钥管理接口。

      后续 MCP 的正确方向是把 Action Definition 映射成 Tool，再通过 localhost Action API 执行，而不是在 MCP 层重新实现表格、媒体、生成和 Job 逻辑。

      31.9 Revision、幂等、Transaction 与 Undo#

      workspaceRevision / expectedRevision#

      TEXT
      最新 Revision 一致 → 执行
旧 Revision → STALE_WORKSPACE → 不提交

      idempotencyKey#

      TEXT
      同 Key + 同 Payload → 复用原响应，idempotentReplay=true
同 Key + 不同 Payload → IDEMPOTENCY_CONFLICT

      对付费生成尤其重要：请求状态不明时先查 Job，不要换新 Key 盲目再次提交。

      Transaction#

      TEXT
      transaction.preview
→ 只计算步骤与 Effects，不提交

transaction.execute
→ 在克隆 Workspace 上执行全部纯数据 Mutation
→ 任一步失败：全部不提交
→ 全部成功：一次 commit + 一个 Undo Token

      Undo / Redo#

      BAT
      node scripts/table_action_client.mjs undo.apply --token=test-123456 --confirmed --params="{\"undoToken\":\"undo_x\"}"
node scripts/table_action_client.mjs redo.apply --token=test-123456 --confirmed --params="{\"undoToken\":\"undo_x\"}"

      如果用户在 UI 中已经有后续编辑，旧 Undo/Redo 会拒绝覆盖新的 Revision。

      31.10 Media Instance 与 Effective Context#

      API 操作的是实际媒体实例，不只是 URL 字符串。

      支持：

      • media.get：读取真实实例；
      • media.attach：附加新的本地路径 / URL；
      • media.copy_instance：复制已编辑实例并保留 cropData / trimData；
      • media.list_by_row：读取一行全部媒体；
      • media.get_effective_context：解析 AI 字段真正会使用的 <Picture n> / <Video n> / <Audio n> 顺序；
      • media.set_crop / clear_crop；
      • media.set_trim / clear_trim；
      • media.move / reorder / remove / set_rating。

      Agent 智能裁切#

      标准顺序为 media.list_crop_presets → media.smart_crop_preview → media.smart_crop_apply。Agent 不自行估算裁切坐标；Preview 返回 sourceBoxPx / sourceBoxRatio / effectiveAspect / wouldOverwrite / replacedCrop，确认后以相同 presetId + targets + overrides Apply。

      JSON
      {
  "version": "0.1",
  "action": "media.smart_crop_preview",
  "params": {
    "tableId": "table_xxx",
    "presetId": "face_swap_1_1",
    "overrides": {
      "aspect": "1:1",
      "headshot": {
        "topMargin": 0.14,
        "minTopMargin": 0.06,
        "sideMargin": 0.12,
        "shoulderDepth": 0.6
      }
    },
    "targets": [{ "rowId": "row_1", "fieldId": "field_images", "index": 0 }]
  }
}

      overrides 只影响本次请求，不修改共享预设。紧凑头像接受 aspect + headshot；通用人体预设还接受 aspectMode / aspectCandidates / framing / protection / spacing。其中 framing 是期望景别（软约束），protection 是最低必保范围（硬约束）；只改 framing 不会清除预设原有 protection。两者支持 above_knee / knee / calf / ankle 起点及 startOffset / endOffset。Preview / Apply 的 constraintContract 回显合并后的契约；坐姿等锚点顺序异常返回 ANCHOR_ORDER_CONFLICT。所有目标无效时返回 NO_VALID_TARGETS；目标解析问题进入 skipped[]，识别/求解问题进入 failed[]。

      安全边界：

      • media.attach 不允许外部 Agent 直接伪造 cropData / trimData；
      • Crop 只接受 0–1 比例矩形；
      • Trim 必须满足 0 <= startMs < endMs <= durationMs；
      • mappedUrl / refUrls / refCells 等预览态字段不通过 API 持久化。

      31.13 失联 ComfyUI Job 安全清理#

      v2.6.5 新增：

      TEXT
      job.cleanup_stale.preview
job.cleanup_stale

      它与普通 job.delete_history 不同：

      Action 用途 是否重新判断远端存活 是否同步 Cell 占位
      job.delete_history 用户明确删除普通历史记录 否 否
      job.cleanup_stale.preview 只读预览可证明失联的任务 是 否
      job.cleanup_stale 清理再次核验后仍失联的任务 是 是

      默认必须同时满足：

      1. Job 为非终态 preparing / uploading / creating / queued / running / polling；
      2. 超过 staleAfterMinutes，默认 30 分钟，最低 5 分钟；
      3. 没有 resultUrl / localPath / finalPath；
      4. Provider 为当前可精确检查的 ComfyUI；
      5. 有持久化 taskId；
      6. ComfyUI 当前可访问，并确认该 taskId 同时不在 Queue 与 History。

      以下对象一律保护：

      • completed / failed / cancelled / submission_unknown；
      • 已有结果 URL / 本地结果文件；
      • 尚未超过阈值；
      • ComfyUI 仍报告排队、运行或终态；
      • 远端不可达、状态未知或没有 taskId；
      • 非 ComfyUI Provider。

      标准顺序：

      BAT
      node scripts/table_action_client.mjs job.cleanup_stale.preview --token=test-123456 --params="{\"tableId\":\"table_xxx\",\"staleAfterMinutes\":30}"
node scripts/table_action_client.mjs job.cleanup_stale --token=test-123456 --confirmed --params="{\"tableId\":\"table_xxx\",\"staleAfterMinutes\":30}"

      执行时会再次核验。真正清理后只会：

      • 删除对应本地 Job 历史；
      • 删除精确匹配 jobId 的 Cell networkJob 占位；
      • 保留同 Cell 已完成媒体和其他 Job；
      • 不删除结果文件；
      • 不虚构“远程取消成功”。
