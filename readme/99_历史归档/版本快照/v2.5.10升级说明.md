# Hong's AI Table Studio v2.5.10 修改日志

## 版本定位

v2.5.10 基于 v2.5.9，继续完善现有表格中的**普通文本 / 智能文本大屏编辑体验**。

本版不引入 Flow Canvas / Workflow，不修改 Provider、Skill Runtime、ComfyUI、OSS、Job、AI 图片/视频生成协议等主链路。

核心目标：让长 Prompt 可以在现有表格模式下完成连续编辑、媒体参考、逐行校对，同时保持原表格数据结构和原生文本编辑能力。

---

## 1. 大屏文本编辑：修复原生键盘操作冲突

### 修复范围

大屏纯文本与“引用渲染”编辑器优先使用浏览器原生编辑行为，包括：

- Enter / Shift + Enter
- Delete / Backspace
- Ctrl / Cmd + A
- Ctrl / Cmd + C
- Ctrl / Cmd + X
- Ctrl / Cmd + V
- Ctrl / Cmd + Z
- Ctrl / Cmd + Y
- Ctrl / Cmd + Shift + Z
- Shift + 方向键选择
- Home / End
- 鼠标拖选、双击选词、右键复制粘贴

### 处理方式

大屏编辑器边界只 `stopPropagation()`，**不 `preventDefault()` 常规编辑按键**；Cell 层的 Enter / Delete / Backspace 逻辑也会识别 input / textarea / select / contentEditable 并主动避让。

v2.5.9 已完成 Grid 全局 Copy/Cut/Paste/Delete 与 App Undo/Redo 对 contentEditable 的避让，本版补齐 Cell 层冲突。

---

## 2. 大屏编辑改为自动保存，不再要求“完成”确认

- 删除额外“完成/确认”流程。
- 关闭大屏时保存当前文本。
- 点击上一行 / 下一行前先保存当前行。
- Ctrl / Cmd + S 仍可主动保存当前内容。

编辑本身即代表修改，不再增加第二次确认。

---

## 3. 新增上一行 / 下一行连续编辑

大屏 Header 新增：

- 上一行
- 当前可见行位置 / 总可见行数
- 下一行

切换流程：

1. 保存当前行文本；
2. 切换到同一字段的上一 / 下一可见行；
3. 保持大屏编辑状态；
4. 虚拟列表同步滚动到目标行；
5. 重新加载目标行 Cell 内容与媒体上下文。

第一行 / 最后一行对应按钮自动禁用。

---

## 4. 普通文本“临时参考”重新设计：选择一个智能节点，而不是逐个附件字段

### 废弃旧方案

不再让普通文本用户逐个勾选 Attachment 字段。

### v2.5.10 新方案

普通 `text` 大屏 Header 增加：

`临时参考 [智能节点 ▼]`

候选仅包含：

- AI Text / 智能文本
- AI Image / 智能图片
- AI Video / 智能视频

第一版只允许选择**一个智能节点**。

选择后，普通文本临时继承该智能节点**当前行实际使用的媒体上下文**，用于：

- 顶部媒体缩略图参考；
- 点击进入原媒体大屏预览；
- `@` 菜单插入；
- “引用渲染”模式媒体 Chip。

### 临时性的边界

该选择只存在于当前大屏编辑会话：

- 不写入 Record；
- 不写入 Field Config；
- 不建立永久字段依赖；
- 关闭大屏后清空。

但在大屏内点击上一行 / 下一行时，会继续沿用同一个“参考智能节点”。

例如：

`视频提示` 临时参考 `视频提示优化`

切换到下一行后仍然参考 `视频提示优化`，但会重新解析下一行该节点实际使用的媒体。

---

## 5. Effective Media Context：复用智能节点真实媒体配置

普通文本临时参考不会复制智能节点的输出文本，也不会默认引用智能节点自己的生成结果。

系统读取被选智能节点的**输入媒体配置**：

- AI Text：`aiTextConfig.sourceImageTemplate`
- AI Image：`aiImageConfig.sourceImageTemplate`
- AI Video：`aiVideoConfig.sourceImageTemplate`
- 同时兼容未来已有字段中的 `sourceVideoTemplate / sourceAudioTemplate`

再按模板字段引用顺序解析当前 Record 中真正存在的媒体。

只把真实可承载媒体的字段纳入上下文：

- attachment
- aiImage
- aiVideo
- url

避免普通文本字段被误识别为文件路径。

---

## 6. 媒体按类型独立编号

三类媒体分别独立编号：

- Picture 1 / Picture 2 / ...
- Audio 1 / Audio 2 / ...
- Video 1 / Video 2 / ...

不会把图片、音频、视频混用同一套 1、2、3 序号。

编号逻辑统一用于：

1. 顶部当前行引用媒体；
2. `@` 菜单；
3. Visual Prompt 媒体 Chip。

---

## 7. 媒体配色统一并降低视觉强度

三类媒体保持统一语义：

- 图片：蓝色
- 音频：紫色
- 视频：紫红色

配色相较之前降低一档视觉强度，并在以下区域保持一致：

- 顶部缩略图序号与名称；
- `@` 菜单；
- Visual Prompt Chip；
- 未加载缩略图时的占位图标。

---

## 8. 顶部媒体卡片精简

顶部区域统一显示：

`当前行引用媒体`

每个媒体只保留：

- 方形缩略图；
- Picture / Audio / Video 名称；
- 类型独立序号；
- 原附件裁切 / 扩图角标（如存在）。

删除缩略图下重复显示的来源字段名，例如原来的“参考”二字，降低重复信息。

媒体来源字段仍保留在内部搜索与 Tooltip 中，不影响调试和定位。

---

## 9. Visual Prompt：首次打开直接显示真实缩略图

修复原问题：

`首次打开引用渲染 → Chip 只有占位图标 → Raw/Visual 切换后才出现缩略图`

现在：

1. 大屏打开后异步生成 / 读取缩略图；
2. Thumbnail Map 更新；
3. Visual DOM 自动重新渲染；
4. 无需用户来回切换模式。

Image / Audio / Video Chip 的图标和文字保持垂直居中。

选择后插入当前光标位置。

菜单只显示当前编辑器有效 Media Context 中存在的媒体。

- `<...>`

只改变渲染，不修改原始文本。

`highlightLargeVisualSyntax()`

## 13. Cell 展开按钮与正文空间优化

### 非编辑状态

普通文本 / 智能文本仍保留右下角浅灰色线性 Expand 按钮：

- 无描边；
- 无投影；
- 轻量 Hover；
- 不抢正文视觉。

### 双击进入 Inline Edit

进入小编辑模式后：

- 不再渲染 Expand 按钮；
- textarea 不再为 Expand 预留右侧 padding；
- 避免遮挡滚动条和正文。

同时 `index.css` 增加表格级保护：只要当前表格存在 Inline Edit，所有其它 Cell 的 Expand 按钮都隐藏，避免鼠标经过下方行时误出现。

### 非编辑正文空间

Text / AI Text 的正文右侧预留从 `pr-8` 收窄为 `pr-6`，约多释放一个中文字宽度。

---

## 14. 智能文本二次生成按钮

已有智能文本结果时：

- Cell 被选中且未进入 Inline Edit，即可直接看到重新生成入口；
- 不再要求双击编辑后才能生成；
- Inline Edit 内不放生成按钮，避免遮挡正文；
- 按钮视觉沿用现有 AI Image / AI Video 的白底 + 紫色渐变 Hover 体系。

大屏 Header 同样提供“重新生成”。
