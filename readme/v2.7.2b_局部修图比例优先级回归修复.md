# v2.7.2b 维护补丁：局部修图第一张源图比例优先级修复

## 问题原因

原 v2.7.2 保存了局部修图裁切比例选择逻辑：`Grid.tsx` 读取 `sourceImageTemplate` 所引第一张有 `cropData.ratio` 的附件，选择最近的标准画幅。但 v2.7.2b 为 Qwen 普通图生图加入“自动/显式比例”时，Qwen 的请求组装又读取 `ratioRaw`（比例下拉的原始值），从而绕过了局部修图得出的 `ratio`。

若局部修图比例框是“自动”而首图保存了 3:4 裁切信息，旧 Qwen 分支会省略 `aspectRatio`，用 TextEncodeQwenImage21 的原生 latent。若比例框是手选 9:16，则会改为 9:16 EmptyLatentImage，即使源图裁切框是 3:4。这两种都违反了局部修图比例的历史优先级。

## 修复后的规则

| 场景 | 生效比例 | Qwen KSampler latent |
| --- | --- | --- |
| 文生图 | 比例参数（自动缺省 1:1） | 节点90 EmptyLatentImage |
| 普通图生图，自动/不填比例 | 第一张参考图的比例 | TextEncodeQwenImage21 输出的原生 latent |
| 普通图生图，明确设置比例 | 用户指定比例 | 节点90 EmptyLatentImage |
| **局部修图，有首图 cropData.ratio** | **第一张原始图片保存的取景框比例**，优先于表格比例 | 节点90 EmptyLatentImage |
| **局部修图，首图无 cropData** | **第一张原始图片的实际宽高比**，映射到旧版标准画幅 | 节点90 EmptyLatentImage |

其他 Provider 已有局部修图 `cropData.ratio` 覆盖比例逻辑仍保留；无 cropData 时补充第一张原始图片宽高识别。只查第一张实际图，不会跳到第二张带有 cropData 的图。若第一张图无法读取比例，则中止并给出错误，避免静默提交错误画幅。

Qwen 局部修图的第一张源图会优先于提示词附加参考图，接入 `images.image_1`。实际保存的裁切区域像素大小仍由 `scaleToSource` 独立控制，未改其计算公式；改为仅从第一张图取裁切参数，避免第二张数据被误用。

## 修改范围

- `src/components/Grid.tsx`: 图像比例选择、Qwen 参数、首图上传顺序、预览比例显示和裁切尺寸来源。
- `src/lib/retouchAspectRatio.js`: 共用的首图选取、旧比例标准化及请求优先级。
- `tests/retouch_aspect_ratio.test.mjs`: 比例优先级、参考图顺序、Qwen EmptyLatentImage 请求等 6 项测试。
- 本文及 Qwen 工作流 README、图片 Map 中文文档与完整版手册。

`comfyui/workflows/qwen-image-2.1/image_api.json` **不需再改**：v2.7.2b 已声明原生节点 90 `EmptyLatentImage`，本次修的是前端没有把局部修图得出的正确比例交给现成的 latent 路由。
