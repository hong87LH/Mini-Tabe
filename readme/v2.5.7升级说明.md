# Hong's AI Table Studio v2.5.7 升级说明

## 版本定位

v2.5.7 基于 v2.5.6 的 **Skill System v1.0**，补充 Skill 稳定性修复，并新增图片、视频和音频的批量附件分类导出。

本次开发遵循两个原则：

1. **兼容原智能文本节点。** Skill 为可选能力；未配置 Skill 时，继续执行 v2.5.5 原有 Prompt、参考字段、参考图片、模型选择和 Provider 请求逻辑。
2. **控制改动范围。** 不重写文本 Provider，不增加 Agent Loop，不执行 Skill 脚本，不修改图片/视频/ComfyUI Workflow 运行链路。

---

## 1. Skill System v1.0

项目根目录新增：

```text
skills/
├─ catalog.json
├─ registry.json
└─ ...用户 Skill 文件夹
```

Skill 的真实内容始终保存在项目源码目录中。`registry.json` 只是启用状态和扫描索引，不是 Skill 本体。

扫描逻辑会递归搜索 `skills/` 下包含 `SKILL.md` 的目录。用户将自己的 Skill 文件夹或旧 Skill 库复制进来后，在设置中点击“扫描目录”即可自动发现并注册。

### Skill 显示名

用户侧统一使用 **显示名**：

```text
MiniMax H3 Prompt Writing
```

显示名来源优先级：

```text
agents/openai.yaml → interface.display_name
SKILL.md frontmatter → display_name
SKILL.md frontmatter → name
文件夹名
```

智能文本字段、字段引用和 Skill 管理界面全部围绕显示名交互。

如果存在两个相同显示名，系统会标记冲突，并拒绝智能文本调用，避免错配到错误 Skill。

## 2. Skill 管理界面

“API 和模型配置”新增内部 Tab：

```text
API 与模型 | Skills
```

原 API 配置内容不拆分、不重写。

Skills Tab 支持：

- 扫描项目 `skills/` 目录；
- 自动注册新复制的 Skill；
- 启用 / 停用；
- 二次确认后卸载 Skill；
- 显示 Skill 描述、相对路径、Reference 数量；
- GitHub 安装的 Skill 显示公开来源；
- 本地复制 / 私有 Skill 显示为 `Custom`，不伪造来源；
- 检测重复显示名；
- 识别 `scripts/`，但 v1.0 不执行。

## 3. 第一个 Skill Library 条目

`skills/catalog.json` 首个条目：

```text
MiniMax H3 Prompt Writing
https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills/h3-prompt-writing
```

用户可在 Skill Library 点击安装。

安装流程：

```text
GitHub Skill 目录
→ 下载完整 Skill 文件夹
→ 写入项目 /skills
→ 写入来源元数据
→ 扫描
→ 注册
```

同时支持用户手动粘贴公开 GitHub Skill 目录地址安装。

v1.0 安装器只接受 `github.com` 公开目录地址，并增加文件数量与总大小限制；不会执行下载到 Skill 中的任何脚本。针对 `ECONNRESET`、连接超时、DNS 临时失败、HTTP 429 和 5xx 等瞬时网络问题，安装器最多自动重试 3 次，并采用 500 ms、1 s、2 s 的递增等待。

## 4. 智能文本节点

智能文本设置新增：

```text
Skill（显示名，可引用字段）
```

支持两种方式：

### 固定选择

```text
MiniMax H3 Prompt Writing
```

### 引用字段

```text
{Skill}
```

表格字段中存放的也是用户看到的 Skill 显示名，因此不需要暴露内部 ID。

字段引用为空时：

```text
不使用 Skill
→ 完全执行原智能文本逻辑
```

引用的 Skill 不存在、已停用或显示名冲突时：

```text
明确报错
→ 不静默退回普通智能文本
```

## 5. Skill Runtime v1.0

v1.0 定义为：

> **Preloaded Structured Skill Context Runtime / 预加载结构化 Skill 上下文运行时**

它不是完整 Agent Runtime。

执行流程：

```text
智能文本字段
→ 解析 Prompt 字段引用
→ 解析 Skill 显示名 / Skill 字段引用
→ Skill Registry
→ 读取 SKILL.md
→ 读取 references/ 文本资料
→ Skill Context Compiler
→ 结构化为一个完整 Prompt
→ 原智能文本 Provider
→ 一次 LLM 请求
→ 写回结果
```

### 结构化上下文

不是简单执行：

```text
SKILL.md + ref1 + ref2 + 用户 Prompt
```

而是保留清晰边界：

```text
<skill_runtime>

<skill_context>
  <skill_metadata />
  <skill_instructions source="SKILL.md">
  <skill_resources>
    <skill_file path="references/...">

<runtime_context>

<current_task>
```

每个 Reference 都保留原文件路径，方便模型理解哪个段落来自哪个文件。

Reference 会被明确标记为“支持资料 / 格式示例”，避免模型把示例剧情误认为当前用户需求。

### 用户实际需求的位置

当前行数据位于：

```text
<runtime_context>
```

用户真实任务位于整个结构最后：

```text
<current_task>
```

因此模型先获得 Skill 方法和参考资料，最后聚焦本次真实任务。

### Provider 兼容策略

v1.0 **没有修改现有 OpenAI / Gemini / ModelScope / Ollama 等文本请求结构**。

Skill Runtime 最终编译出一段结构化文本，再继续走原来的单条用户消息请求链路。

这样可以最大限度保证：

```text
没有 Skill → 原逻辑完全不变
有 Skill   → 只替换最终 Prompt 内容
Provider   → 不需要感知 Skill
```

这是本次兼容性设计的核心。

## 6. v1.0 支持范围

支持：

```text
✓ SKILL.md
✓ references/*.md
✓ references/*.txt
✓ references/*.json
✓ references/*.yaml / *.yml
✓ agents/openai.yaml UI 元数据
✓ 项目目录扫描
✓ 用户复制 Skill 文件夹
✓ GitHub 公开 Skill 安装
✓ 来源记录
✓ 启用 / 停用
✓ 固定 Skill
✓ Skill 字段引用
✓ 一次 LLM 调用
```

暂不支持：

```text
× scripts 执行
× Shell
× Python
× MCP
× Tool Calling
× Agent Loop
× 多 Skill Stack
× Auto Skill 自动选择
× Reference 按需二次读取
× Skill 在线更新检测
```

这些能力没有为了“看起来完整”而提前加入，避免破坏现有稳定链路。

## 7. 批量附件导出增强

批量下载功能由仅识别图片扩展为统一的附件媒体导出：

- 支持图片、视频和音频附件；
- 支持普通附件字段、智能图片字段和智能视频字段；
- 导出弹窗可选择“全部 / 图片 / 视频 / 音频”；
- 根据附件 MIME、文件名、URL 扩展名及本地媒体协议识别类型；
- 无扩展名且缺少 MIME 的旧附件链接继续按图片处理，保持历史数据兼容；
- 自动保留附件原文件名和扩展名；使用字段命名模板时，根据媒体类型生成正确扩展名；
- ZIP 文件按选择类型命名为 `attachments_*`、`images_*`、`videos_*` 或 `audios_*`。
