# 1. 工具是什么

Hong's AI Table Studio 是一款把“多维表格”和“AI 内容生成”组合到一起的桌面工具。它可以像飞书多维表格、Airtable 或 Excel 一样管理一行一行的数据，同时让每一行调用 AI 生成文本、图片或视频。

典型用途包括：

- 按货号、颜色、渠道管理商品视觉任务；
- 通过表格批量生成标题、卖点、提示词和描述文案；
- 一行放多张参考图，再批量调用 AI 生图；
- 用首帧、尾帧、参考视频或音频生成视频；
- 对图片打分、打点批注、记录修改意见；
- 将生成结果按货号、颜色、渠道自动命名并保存；
- 将本地参考图上传到阿里云 OSS，供灵悟 AI 等接口读取；
- 在后台任务中心查看长时间运行的图片、视频任务；
- 软件重启后继续部分未完成任务，或重试下载已生成的结果；
- 从后台任务一键跳回当时点击生成的原单元格；
- 查看当前 OSS Bucket 容量，并按日期清理较旧的参考素材。

## 1.1 推荐使用方式

本版本同时包含网页前端和 Electron 桌面能力，但日常工作建议使用 **Electron 桌面模式**。

| 能力 | Electron 桌面模式 | 浏览器模式 |
|---|---:|---:|
| 普通表格编辑 | 支持 | 支持 |
| 文本 API 调用 | 支持 | 支持，但可能受跨域限制 |
| 普通远程图片生成 | 支持 | 部分支持 |
| 灵悟 AI 图片生成 | 支持 | 不支持 |
| 灵悟 AI 视频生成 | 支持 | 不支持 |
| 后台 Job、自动轮询和本地下载 | 支持 | 不完整 |
| 读取本地文件绝对路径 | 支持 | 不支持或受限制 |
| 静默保存到指定文件夹 | 支持 | 不支持 |
| Photoshop 联动 | 支持 | 不支持 |
| OSS 上传本地参考素材 | 支持 | 不完整 |
| OSS 容量查看与清理 | 支持 | 不支持 |

> **结论：** 只做普通表格或文本测试时可使用浏览器模式；涉及本地图片、灵悟 AI、视频、后台任务、批量落盘或 OSS 时，应使用 Electron 桌面模式。

# 2. 使用前先理解五个概念

## 2.1 工程

工程是一整份工作文件，扩展名通常为：

```text
.aistudio.json
```

一个工程可以包含多张表。

## 2.2 表格

表格相当于工作簿中的一个工作表。例如：

- 主任务表
- 提示词表
- 生图结果表
- 视频任务表
- 审核记录表

## 2.3 字段

字段就是“列”。例如：

- 货号
- 颜色
- 参考图片
- 提示词
- 智能图片
- 评分

每个字段都有固定类型，字段类型决定这一列可以输入什么内容、如何显示、是否能调用 AI。

## 2.4 记录

记录就是“行”。通常一行代表一个任务、一个货号、一个颜色或一个镜头。

## 2.5 引用字段

AI 提示词中可以用大括号引用同一行其他字段：

```text
为货号 {货号} 的 {颜色} 产品生成一张电商主图，场景为 {场景要求}。
```

运行到某一行时，系统会自动把 `{货号}`、`{颜色}`、`{场景要求}` 替换成该行的真实内容。

> 字段名称必须与大括号中的名称完全一致。重命名字段后，要同步修改所有公式和 AI 提示词中的引用。

# 3. 安装与启动

当前压缩包是 Node.js 源码项目，不是双击即可运行的正式安装包。第一次使用时需要先安装 Node.js。

## 3.1 推荐环境

- Windows 10 或 Windows 11；
- macOS 也可运行，但本指南以 Windows 为主；
- Node.js 22.x；
- npm 10.x；
- 稳定网络；
- 至少 8 GB 内存，推荐 16 GB 及以上；
- 如需批量处理大图或视频，建议预留足够磁盘空间。

## 3.2 安装 Node.js

1. 安装 Node.js 22.x。
2. 安装过程中保持默认选项。
3. 安装完成后打开 PowerShell。
4. 输入：

```powershell
node -v
npm -v
```

如果能看到版本号，说明安装成功。

示例：

```text
v22.x.x
10.x.x
```

## 3.3 解压项目

将压缩包解压到一个路径较短、无特殊权限限制的文件夹，例如：

```text
D:\AI-Tools\Hongs-AI-Table-Studio
```

不建议直接放在：

- `C:\Program Files`；
- 系统目录；
- 路径过深的文件夹；
- 需要管理员权限才能写入的位置。

## 3.4 打开终端

在项目文件夹空白处：

1. 按住 `Shift`；
2. 单击鼠标右键；
3. 选择“在终端中打开”或“在 PowerShell 中打开”。

也可以手动执行：

```powershell
cd "D:\AI-Tools\Hongs-AI-Table-Studio"
```

## 3.5 安装依赖

首次运行执行：

```powershell
npm ci
```

若 `npm ci` 因锁文件或依赖状态失败，可改用：

```powershell
npm install
```

安装完成后，项目文件夹中会出现 `node_modules` 文件夹。

## 3.6 启动桌面端

执行：

```powershell
npm run dev
```

该命令会同时启动：

1. Vite 前端服务；
2. Electron 桌面窗口。

看到桌面应用窗口后即可使用。运行期间不要关闭终端窗口。

## 3.7 只启动浏览器版

仅测试基础界面时可执行：

```powershell
npm run dev:react
```

终端会显示一个本地地址，通常类似：

```text
http://localhost:5173
```

在浏览器中打开即可。

> 浏览器版无法完整使用灵悟 AI、本地路径、Photoshop 和静默批量保存等桌面能力。

## 3.8 关闭工具

1. 先保存工程；
2. 关闭 Electron 窗口；
3. 回到终端按 `Ctrl + C`；
4. 如终端询问是否终止任务，输入 `Y`。

# 4. 第一次打开后的推荐设置

建议按以下顺序完成初始化。

## 4.1 设置团队身份

打开设置，在“团队身份（用户名）”中填写自己的名字或岗位，例如：

```text
李明-电商设计
```

该名称会用于图片批注和回复记录。

## 4.2 立即保存一个工程

首次打开后，不要只依赖浏览器缓存。先执行：

```text
保存 → 另存为
```

建议工程命名：

```text
2026秋冬童装视觉任务.aistudio.json
```

## 4.3 配置 API

打开“API 和模型配置”，至少配置一组实际可用的模型提供商。配置方法见第 11 章。

## 4.4 设置自动备份

工程已经保存后，再开启“项目自动备份”。自动备份会在工程所在目录生成同名 `.backup` 文件。

推荐间隔：

- 普通编辑：5 分钟；
- 大批量 AI 任务：2～5 分钟；
- 低频使用：10 分钟。

## 4.5 灵悟 AI 用户配置 OSS

若需要把本地图片作为灵悟 AI 的参考图，应先完成 OSS 配置。

v2.4.8 推荐每位同事使用自己独立的 Bucket。需要填写：

- Access Key ID；
- Access Key Secret；
- Endpoint；
- Bucket Name。

Domain 会根据 Endpoint 和 Bucket 自动生成，不需要手动填写。

> 切换 Bucket 前先确认名称和区域。不同员工的 Bucket、CSV 索引和容量不要混用。

## 4.6 先认识后台任务中心

图片或视频任务提交成功后，可能不会一直占住当前单元格等待，而是进入后台任务中心继续轮询和下载。

建议第一次使用时先找到右上角的后台任务入口，了解以下按钮：

- 跳转原单元格；
- 写回原单元格；
- 继续轮询；
- 重试下载；
- 查看远程结果；
- 打开本地文件；
- 删除任务记录。

这样即使网络中断、下载失败或软件重启，也知道去哪里继续处理。

# 5. 界面结构

## 5.1 左侧栏

左侧栏用于管理：

- 工程名称；
- 多张表格；
- 新增、重命名、复制、删除表格；
- 调整表格顺序；
- 表格图标。

左侧栏默认可能处于收起状态，可点击左上角按钮展开。

## 5.2 顶部工程栏

常用入口包括：

- 新建工程；
- 打开工程；
- 导入 JSON；
- 导入 CSV；
- 保存；
- 另存为；
- 导出 JSON；
- 导出 CSV；
- 设置；
- 后台任务中心。

## 5.3 视图切换

当前版本提供两种主要视图：

### 默认视图

用于录入、修改、筛选、排序、AI 生成和批量处理。

### 图片审阅

用于集中查看图片、评分、批注和筛选审阅状态。

## 5.4 表格工具栏

默认视图上方常见功能：

- 隐藏字段；
- 筛选；
- 分组；
- 排序；
- 行高；
- 搜索；
- 添加记录。

## 5.5 后台任务中心

后台任务中心是右侧抽屉面板，用于查看灵悟图片和视频任务。

每张 Job 卡片通常会显示：

- 当前阶段；
- 使用模型；
- 本地 Job ID；
- 远程 task_id；
- 远程结果链接；
- 本地保存结果；
- 最近一次错误。

常用操作：

- **跳转原单元格：** 回到当时发起生成的位置；
- **写回原单元格：** 将已下载结果重新写入原单元格；
- **继续轮询：** 对仍有 task_id 的任务继续查询；
- **重试下载：** 已经生成成功但本地下载失败时继续下载；
- **垃圾桶：** 删除本地 Job 记录。

点击“跳转原单元格”后，任务侧栏会继续保持展开，方便连续检查多个任务。

Bucket 默认不会出现在所有卡片上。只有任务属于历史 Bucket，或发生 OSS、参考图上传错误时，卡片才会显示 Bucket 提示。

## 5.6 OSS 容量区域

设置页面的 OSS 区域可以：

- 刷新当前 Bucket 容量；
- 查看已用容量和参考套餐容量；
- 查看是否达到清理线；
- 查看计划删除的日期目录；
- 手动执行清理。

容量管理只针对当前设置中的 Bucket，不代表其他同事的 Bucket。

# 6. 工程与表格管理

## 6.1 新建工程

点击“新建工程”会创建一份新的空白项目。新建前务必先保存当前工程。

## 6.2 打开工程

点击“打开工程”，选择 `.aistudio.json` 文件。

工具会记录最近打开过的工程。若浏览器或系统权限发生变化，最近记录中的文件可能需要重新授权。

## 6.3 修改工程名称

展开左侧栏，点击工程名称进行修改。

注意：界面中的工程名称与磁盘上的文件名不是完全同一概念。修改界面名称后，建议再执行一次“另存为”，让文件名保持一致。

## 6.4 新增表格

在左侧栏点击添加表格按钮。新表会生成默认字段和空记录。

## 6.5 重命名表格

双击表格名称，输入新名称后按 `Enter` 保存，按 `Esc` 取消。

## 6.6 复制表格

复制表格会复制其：

- 字段结构；
- 字段设置；
- 现有记录；
- AI 字段配置。

适合从模板快速创建新渠道、新批次或新项目表。

## 6.7 删除表格

删除后无法通过普通方式恢复，因此先保存工程或导出 JSON。系统不允许删除最后一张表。

## 6.8 调整表格顺序

按住左侧栏中的表格条目拖动，即可更改顺序。

# 7. 字段类型说明

点击字段标题左侧的类型图标，可打开字段设置。双击字段名可以重命名。

| 字段类型 | 用途 | 示例 |
|---|---|---|
| 文本 | 普通文字、多行说明 | 货号、需求、提示词 |
| 数字 | 数量、价格、尺寸 | 4、99.9、1080 |
| 单选标签 | 一条记录只能选一个选项 | 待处理、进行中、完成 |
| 多选标签 | 一条记录可选多个选项 | 天猫、京东、唯品会 |
| 日期 | 日期记录 | 2026-07-14 |
| 复选框 | 是/否状态 | 是否加声音 |
| 人员 | 负责人或审核人 | 张三、李四 |
| 链接 | 网页地址或媒体地址 | 产品页 URL |
| 附件 | 图片、视频等素材 | 产品图、首帧图 |
| 公式 | 根据当前行其他字段计算 | `{单价} * {数量}` |
| 评分 | 0～5 星评价 | 图片质量评分 |
| 智能文本 | 调用 AI 生成文字 | 标题、卖点、翻译 |
| 智能图片 | 调用 AI 生成图片 | 主图、场景图、修图 |
| 智能视频 | 调用 AI 生成视频 | 图生视频、视频扩展 |

## 7.1 文本字段

适合货号、颜色、要求、说明和长提示词。编辑时：

- `Enter`：保存并移动到下一行；
- `Alt + Enter`：在单元格内换行；
- `Esc`：退出编辑。

## 7.2 数字字段

输入内容会转换为数字。粘贴无法转换的文字时可能变为空值或异常值，建议先清洗数据。

## 7.3 单选与多选字段

可在字段设置中管理选项、名称和颜色。粘贴外部文本时，系统会尽量按选项名称匹配。

## 7.4 附件字段

可加入多张图片或多个媒体文件。新加入的附件会追加到现有内容，不会自动覆盖原附件。

常用操作：

- 点击单元格上传；
- 将文件拖入单元格；
- 拖动附件调整顺序；
- 删除、复制或下载单个附件；
- 点击缩略图进入大图预览。

> 当前文件选择器主要显示图片和视频。音频作为视频模型参考时，建议直接拖入附件单元格，或使用可访问的音频 URL。

## 7.5 公式字段

公式通过字段名引用当前行数据：

```text
{单价} * {数量}
```

也可以使用等号开头的表达式：

```text
={总额} - {优惠}
```

字符串拼接可使用：

```text
={货号} & "_" & {颜色}
```

当前引擎会将 `&` 转换为字符串加号处理。

注意事项：

- 公式字段主要用于显示计算结果，不建议手动输入；
- 字段重命名后，公式不会自动更新；
- 尽量使用简单数字和字符串表达式；
- 不要把未知脚本或不可信表达式粘贴到公式中。

## 7.6 评分字段

用于图片筛选、审阅和批量下载。可设置 1～5 星；未评分视为 0 星。

# 8. 基础录入与表格操作

## 8.1 新增记录

点击工具栏中的“添加记录”，或在已有记录下方继续添加。

## 8.2 编辑单元格

- 单击：选中；
- 双击或按 `Enter`：进入编辑；
- `Esc`：退出编辑；
- `Delete` / `Backspace`：清空选中单元格。

## 8.3 连续选择区域

从一个单元格拖动到另一个单元格，可选择矩形范围。

按住：

- `Shift`：扩展连续选择；
- `Ctrl` / `Command`：追加非连续单元格选择。

## 8.4 复制、剪切与粘贴

支持类似 Excel 的矩形复制粘贴：

- `Ctrl + C`：复制；
- `Ctrl + X`：剪切；
- `Ctrl + V`：粘贴。

从 Excel 或 CSV 软件复制的数据，以制表符和换行识别行列。若粘贴内容超过现有行数，系统可自动增加记录。

附件、智能图片和智能视频字段在粘贴 URL 时采用追加方式。

## 8.5 删除记录

选中一行或多行后右键，选择“删除 N 行”。

# 10. 数据导入、导出、保存与备份

这是最容易混淆的部分。v2.4.8 有工程文件、CSV、浏览器缓存、自动备份和后台 Job 记录几套不同机制。

## 10.1 五种数据机制的区别

| 机制 | 保存内容 | 主要用途 |
|---|---|---|
| 工程文件 `.aistudio.json` | 多张表、字段、记录、AI 字段配置 | 完整继续工作 |
| CSV | 当前表格的扁平数据 | Excel 交换、运营交付 |
| 浏览器本地缓存 | 最近编辑状态和本机偏好 | 临时恢复，不应作为唯一备份 |
| `.backup` 自动备份 | 当前工程数据副本 | 防止误关、崩溃或覆盖 |
| `network-jobs.json` | 后台任务阶段、task_id、结果地址和写回位置 | 恢复长时间运行的图片、视频任务 |

## 10.2 保存工程

使用“保存”或快捷键：

```text
Ctrl + S
```

第一次保存时需要选择文件位置。之后“保存”会尝试写回原文件。

## 10.3 另存为

用于：

- 创建版本副本；
- 更改文件名；
- 保存到其他目录；
- 开始新批次前保留旧版本。

推荐命名：

```text
项目名_日期_版本.aistudio.json
```

示例：

```text
秋冬家居服主图_20260802_v03.aistudio.json
```

## 10.4 导入 JSON

支持两类 JSON：

1. 完整工程；
2. 单张表结构。

拖入 JSON 时，系统可能询问是替换当前工程还是追加到当前工程。替换前先保存。

## 10.5 导入 CSV

导入 CSV 后，所有列默认按文本字段创建。需要数字、附件、AI 或标签类型时，应在导入后手动修改字段类型。

建议 CSV 使用 UTF-8 编码，避免中文乱码。

## 10.6 导出 JSON

导出 JSON 可作为完整工程备份或跨设备转移文件。

## 10.7 导出 CSV

CSV 只导出当前表格：

- 公式字段导出计算后的结果；
- 附件、智能图片、智能视频导出为逗号分隔的 URL；
- 单选、多选导出显示名称；
- 不会保留字段颜色、AI 配置和批注意义结构。

因此，CSV 不能替代工程文件。

## 10.8 自动备份

开启前必须先保存工程。开启后系统按设定间隔写入同目录 `.backup` 文件。

推荐工作方式：

```text
工程文件 + 自动备份 + 每日另存版本
```

## 10.9 后台 Job 记录

后台任务记录保存在 Electron 用户数据目录中的：

```text
network-jobs.json
```

Job 记录保存任务信息，不保存图片或视频文件本体。

当前自动整理规则：

- 已完成且超过 30 天的 Job 会在软件启动时清理；
- 非 `submission_unknown` 的任务最多保留约 500 条；
- `submission_unknown` 不会被自动删除；
- 卡片右上角垃圾桶可以手动删除记录。

> 删除 Job 记录不等于取消远端付费任务。运行中的任务删除后，后续结果可能无法自动轮询、下载或写回。

## 10.10 不会随工程文件保存的内容

以下设置保存在当前电脑，不属于工程文件主体：

- API 提供商配置；
- API Key；
- OSS 配置；
- Photoshop 路径；
- 团队用户名；
- 自动备份偏好；
- 后台 Job 历史；
- 已下载文件和 `.part` 临时文件。

换电脑时需要重新配置，或通过“API 配置导出”迁移。后台 Job 不会自动跟随工程文件复制到另一台电脑。

# 11. API 与模型配置

打开“API 和模型配置”。当前分为：

- 文本模型提供商；
- 图片模型提供商；
- 视频模型提供商；
- OSS 图床配置；
- Photoshop 路径。

## 11.1 提供商格式

每个提供商可选择：

| 格式 | 适用情况 |
|---|---|
| OpenAI Format | OpenAI 官方或 OpenAI 兼容中转接口 |
| Gemini Format | Gemini 文本接口 |
| Gemini Custom | 自定义 Gemini 图像或文本接口 |
| 灵悟AI Format | 灵悟 AI 图片或视频接口 |

## 11.2 每项配置的含义

### 提供商名称

仅用于自己识别，例如：

```text
公司中转-文本
灵悟-图片
灵悟-视频
Gemini-图片
```

### Endpoint

接口基础地址。

OpenAI 兼容文本接口通常填写到 `/v1` 层级，例如：

```text
https://example.com/v1
```

系统会自动补充：

```text
/chat/completions
```

OpenAI 兼容图片接口会自动使用：

```text
/images/generations
```

Gemini 基础地址未包含 `:generateContent` 时，系统会自动补充模型路径。

灵悟 AI 填基础地址，程序主要调用：

```text
POST /v1/media/generate
GET  /v1/media/status?task_id=...
```

如果主要状态接口返回 404 或 405，程序会回退到旧状态路径：

```text
GET /v1/skills/task-status?task_id=...
```

### API Key

模型服务商提供的密钥。没有有效 Key 无法生成。

### 模型

多个模型用英文逗号分隔：

```text
gpt-4o-mini,gpt-4.1-mini
```

第一组提供商、第一项模型通常作为默认值。

## 11.3 灵悟图片模型 Profile

v2.4.8 会根据模型名称使用不同参数和参考图规则。

| 模型 | 请求规则 | 参考图规则 |
|---|---|---|
| `gemini-3-pro-image-preview` | 使用 `imageSize`、`aspectRatio` | JPEG Quality 95、4:4:4、独立 OSS 目录和 CSV |
| `gemini-3.1-flash-image-preview` | 使用 `imageSize`、`aspectRatio` | JPEG Quality 95、4:4:4、独立 OSS 目录和 CSV |
| `doubao-seedream-5-0-260128` | 转换为即梦使用的 `size`、`aspect_ratio` | 使用普通 WebP 参考图 Profile |
| 其他灵悟图片模型 | 使用兼容的尺寸映射 | 使用普通 WebP 参考图 Profile |

两个灵悟 Gemini 图片模型支持的参考图数量上限配置为 14 张。

## 11.4 多提供商匹配逻辑

可以配置多组提供商。AI 字段若指定了模型名称，系统会查找“模型列表中包含该模型”的提供商。

例如：

| 提供商 | 模型列表 |
|---|---|
| A | `gpt-4o-mini,gpt-4.1-mini` |
| B | `deepseek-chat,deepseek-reasoner` |

某一行模型字段填写 `deepseek-chat` 时，会自动使用 B 提供商。

如果找不到完全匹配的模型，将回退到第一组提供商。

## 11.5 导入和导出配置

支持：

- 导入配置；
- 导出不含密钥；
- 导出含密钥。

“导出含密钥”的文件包含 API Key 和 OSS Secret，等同于密码文件。不要发送到群聊、公共网盘或 GitHub。

## 11.6 最小配置示例

### 文本模型

```text
名称：文本接口
格式：OpenAI Format
Endpoint：https://你的服务地址/v1
API Key：你的密钥
模型：你的模型名称
```

### 灵悟图片模型

```text
名称：灵悟图片
格式：灵悟AI Format
Endpoint：灵悟服务基础地址
API Key：你的灵悟密钥
模型：gemini-3-pro-image-preview,gemini-3.1-flash-image-preview
```

### 灵悟视频模型

```text
名称：灵悟视频
格式：灵悟AI Format
Endpoint：灵悟服务基础地址
API Key：你的灵悟密钥
模型：veo3.1,grok-video-3,kling-v3-video
```

模型名必须与服务端实际支持名称一致。

## 11.7 配置安全

后台 Job 需要保存部分任务凭证，以便软件重启后继续轮询。Electron 支持时会使用系统安全存储加密后写入 Job 文件。

仍然建议：

- 不把 Job 文件发给其他人；
- 不把含密钥配置提交到 GitHub；
- 电脑更换或人员离职时更换密钥；
- OSS 使用 RAM 子账号和最小权限。

# 13. 智能图片使用方法

## 13.1 创建智能图片字段

1. 新增字段；
2. 类型选择“智能图片”；
3. 打开字段设置；
4. 配置提示词、参考图、分辨率、比例、数量、模型和保存位置；
5. 保存设置。

## 13.2 提示词示例

```text
基于参考产品图生成电商商业摄影图。
产品款式、颜色、Logo、面料纹理与工艺必须保持一致。
场景：{场景}
构图：{构图}
光线：自然柔光，真实阴影。
画幅：{比例}
不要文字，不要水印，不要新增产品。
```

## 13.3 原始图片

“原始图片”用于指定参考素材字段，例如：

```text
{正面图}{背面图}{细节图}
```

也可以通过右侧“+ 引用”选择字段，避免手动输入错误。

可引用字段类型：

- 附件；
- 智能图片；
- 智能视频；
- 链接。

## 13.4 分辨率

界面预设：

- 1K；
- 2K；
- 4K。

也可引用某一字段：

```text
{输出分辨率}
```

灵悟 Gemini 图片模型会使用 `1K/2K/4K` 的 `imageSize`。即梦 5 会将界面分辨率转换为它支持的 2K 或 3K。其他模型可能转换成具体像素尺寸。

## 13.5 比例

界面常用预设：

- 1:1；
- 16:9；
- 9:16；
- 4:3；
- 3:4。

也可引用字段：

```text
{图片比例}
```

灵悟 Gemini Profile 还允许 2:3、3:2、4:5、5:4、21:9 等比例，但界面未列出的比例通常需要通过引用字段传入。

## 13.6 生成数量

每次可设置 1～10 张。

注意：

- OpenAI 兼容接口通常一次请求传入数量；
- Gemini Custom 会并行发起多个请求；
- 灵悟图片会为每张结果建立独立后台 Job；
- 数量越多，付费任务数量、轮询时间和下载任务也越多。

## 13.7 文件名模板

示例：

```text
{货号}_{颜色}_{渠道}_{序号}
```

如果系统接口未提供 `{序号}` 特殊变量，建议在表中建立“序号”字段再引用。

## 13.8 保存目录

Electron 模式可以填写本地目录，例如：

```text
D:\AI_Output\主图
```

浏览器模式无法按绝对路径静默保存。

如果目标目录已有同名文件，程序会自动增加序号，不会直接覆盖。

## 13.9 模型选择

可填写固定模型名，也可引用模型字段：

```text
{图片模型}
```

模型名必须出现在某个图片提供商的模型列表中，否则会回退到默认提供商。

## 13.10 不同图片接口的注意事项

### OpenAI Format

系统调用 `/images/generations`，并请求 Base64 结果。若同时传参考图，会附加 `base64Array` 参数。

`base64Array` 不是所有官方或兼容接口都支持。若文生图正常、参考图生图报错，需要确认代理服务是否支持该扩展参数。

### Gemini Format

普通 `Gemini Format` 主要用于文本。当前图片工作流建议使用 Gemini Custom、OpenAI 兼容图片接口，或灵悟中的 Gemini 图片模型。

### Gemini Custom

可发送多张内联参考图，适合兼容 Gemini 图像生成的自定义接口。

### 灵悟AI Format

必须在 Electron 桌面端运行。使用本地参考图时通常需要 OSS。

灵悟图片任务提交后，会进入后台 Job 流程，不需要一直停留在当前单元格等待。

## 13.11 单元格中的生成状态

发起灵悟图片任务后：

- 空单元格会显示 `Generating...` 或 Job 占位状态；
- 已经有内容的单元格会保留原内容，同时显示新任务状态；
- 任务完成并下载成功后，最终图片会写入单元格；
- Job 占位状态会自动移除；
- 同一个完成事件重复到达时，不应重复添加相同结果。

## 13.12 任务提交后不要盲目重复点击

如果创建任务时发生超时，系统可能把任务标为：

```text
submission_unknown
```

它表示：请求可能已经到达服务器，但本地没有拿到 task_id。

这种情况下不要立即重复点击生成，否则可能产生第二个付费任务。先在后台任务中心保留记录并确认服务商后台。

# 14. 多参考图与模型参考图规则

v2.4.8 保留了多参考图能力，并根据模型分成两套独立的 OSS 参考图 Profile。

## 14.1 多图从哪里来

系统会收集：

1. 提示词中识别到的图片引用；
2. “原始图片”配置中引用的字段；
3. 每个附件字段内部的全部图片；
4. 多个被引用字段中的全部图片。

最终按字段引用顺序和附件内部顺序组成图片数组。

## 14.2 正确配置示例

假设表中有：

- `产品多角度图`：一个附件单元格内有 4 张图；
- `工艺细节图`：一个附件单元格内有 2 张图；
- `风格参考图`：一个附件单元格内有 1 张图。

“原始图片”填写：

```text
{产品多角度图}{工艺细节图}{风格参考图}
```

系统会依次收集 7 张参考图。灵悟 Gemini 图片模型的 Profile 上限为 14 张。

## 14.3 图片顺序为什么重要

某些模型会对前几张参考图赋予更高权重。建议：

1. 第一张放最重要的产品正面图；
2. 第二张放背面或版型图；
3. 中间放 Logo、面料、腰头等工艺细节；
4. 最后放场景或风格参考。

附件单元格内可通过拖动缩略图调整顺序。

## 14.4 两套 OSS 参考图 Profile

### 灵悟 Gemini 图片模型

适用：

```text
gemini-3-pro-image-preview
gemini-3.1-flash-image-preview
```

上传规则：

```text
格式：JPEG
质量：95
色度采样：4:4:4
尺寸：保持原始尺寸
OSS Prefix：references-node-gemini-jpeg-v1/
CSV：oss_references_gemini_jpeg_node.csv
```

### 其他灵悟图片模型

上传规则：

```text
格式：WebP
质量：90
尺寸：保持原始尺寸
OSS Prefix：references-node/
CSV：oss_references_node.csv
```

两套 Profile 的文件和索引相互独立，避免 Gemini 命中旧 WebP 记录。

## 14.5 已经处理好的 JPEG

如果前端已经为 Gemini 生成了 JPEG 参考图，上传器会尽量直接使用该文件，避免重复压缩。

Base64 临时文件上传完成后会自动清理。

## 14.6 推荐提示词写法

```text
参考图 1 为产品正面，参考图 2 为产品背面，参考图 3～5 为工艺和面料细节，最后一张为场景风格参考。
严格保持前五张图中的产品版型、颜色、Logo、包边、缝线和面料质感；仅参考最后一张图的构图、光线和场景，不复制其中的产品。
```

## 14.7 多图仍只收到一张时的检查顺序

1. 确认运行的是 v2.4.8；
2. 确认使用 Electron，而不是浏览器版；
3. 确认“原始图片”引用的是附件字段名称；
4. 确认附件单元格中确实存在多张独立附件；
5. 确认 OSS 配置有效，本地图片能成功上传；
6. 确认灵悟服务端对应模型支持多图；
7. 确认参考图数量没有超过模型上限；
8. 查看后台任务和终端是否有某一张参考图上传失败。

参考图上传不完整时，程序会阻止创建不完整的任务，而不是丢掉失败图片继续生成。

# 15. 智能视频使用方法

当前版本的智能视频运行时主要支持 **灵悟AI Format** 提供商，并且必须使用 Electron 桌面端。

## 15.1 创建智能视频字段

1. 新增字段；
2. 类型选择“智能视频”；
3. 配置提示词；
4. 引用图片、视频或音频素材；
5. 设置模型、比例、分辨率、模式和时长；
6. 保存并生成。

## 15.2 参考媒体

“参考图片/视频”可以引用：

- 附件字段；
- 智能图片字段；
- 智能视频字段；
- URL 字段。

示例：

```text
{首帧}{尾帧}{动作参考视频}{背景音乐}
```

系统会根据扩展名区分媒体：

- 图片：普通图片地址；
- 视频：`.mp4`、`.webm`、`.mov`；
- 音频：`.mp3`、`.wav` 或 `data:audio`。

本地媒体会先上传 OSS。任何一项参考媒体上传失败时，任务会停止创建，避免用缺失素材生成。

## 15.3 视频配置项

### 分辨率/FPS

界面预设：

- 720P；
- 1080P；
- 2K；
- 4K。

不同模型可能忽略、转换或限制该值。

### 比例

预设：

- 16:9；
- 9:16；
- 1:1；
- 4:3；
- 3:4；
- 21:9；
- 2:3；
- 3:2。

### 生成模式

界面主要提供：

- `fast`；
- `quality`。

系统会按具体模型转换成其支持的参数。

### 时长

界面预设：

- 5；
- 10；
- 15；
- 20；
- 25；
- 30 秒。

并非所有模型都支持这些时长。程序会删除、近似映射或转换参数。

### 伴随声音

开启后，系统尝试发送音频生成参数。是否生效取决于模型。

### 优化提示词

开启后，系统尝试发送提示词增强参数。部分模型不支持，会被自动删除。

## 15.4 当前模型参数映射

以下内容以 v2.4.8 的 `video_param_mapper.js` 为准。

| 模型 | 关键映射与限制 |
|---|---|
| `veo3.1` / `veo3.1-4k` | `fast`→`generation_mode=fast`，`quality`→`pro`；比例生效；分辨率和时长会删除 |
| `veo3.1-lite` | 720P/1080P→`quality=sd`，4K→`quality=4k`；模式与时长删除 |
| `grok-video-3` | 分辨率锁为 720P；时长小于等于 6 映射为 6 秒，否则映射为 10 秒；声音与模式删除 |
| `grok-imagine-video-1.5-preview` | 比例直传；分辨率转小写；时长按字符串直传；声音、模式和提示词增强删除 |
| 名称包含 `viduq3` | 模式映射为 turbo/pro；比例、分辨率、时长可传 |
| `viduq3-cankaosheng` | fast/turbo/std→`viduq3`；quality/pro→`viduq3-mix` |
| `vidu-mv` | 首个音频映射到 `audio_url`；比例和分辨率可传 |
| `kling-v3-video` | fast/std→`std`；quality/pro→`pro`；时长和比例可传 |
| `doubao-seedance-1-5-pro-251215` | 时长映射为 `audio_duration`；比例映射为 `ratio`；声音映射为 `generate_audio` |

## 15.5 视频生成提示词示例

```text
基于首帧中的模特和服装生成 10 秒竖屏展示视频。
人物身份、脸部、身材比例、服装款式、颜色、Logo 和面料纹理保持一致。
动作自然：先看向镜头，再缓慢转身展示侧面，最后向前走两步。
镜头为稳定中景，轻微跟随，不要突变，不要多余人物，不要改变服装结构。
```

## 15.6 后台轮询

视频任务创建成功后会保存：

- 本地 Job ID；
- 远程 task_id；
- 当前阶段；
- 原表格、记录和字段位置；
- 结果地址；
- 下载设置。

程序大约每 3 秒查询一次状态。临时网络错误会稍后继续，不会立即重新创建付费任务。

单次轮询最长约 30 分钟。超时后任务会标为失败，但远端任务是否仍在运行需要以服务商后台为准。

## 15.7 软件重启后的恢复

软件重新打开时会：

- 对 `polling` 且有 task_id 的任务继续轮询；
- 对已经生成但未下载完成的任务继续下载；
- 对应用在“创建中”关闭、又没有拿到 task_id 的任务标记为 `submission_unknown`。

## 15.8 下载与断点续传

生成成功后，程序会先写入：

```text
文件名.ext.part
```

下载完成后再改成正式文件名。

网络中断时会保留 `.part`，重试时尝试使用 Range 继续下载。若服务器不支持当前续传位置，程序会删除无效 `.part` 后重新开始。

# 16. 批量工作流与后台任务中心

批量工作流负责从左到右执行 AI 字段；后台任务中心负责管理已经提交到远端、需要长时间轮询和下载的图片或视频任务。

## 16.1 工作流执行顺序

选中一行或多行，右键选择：

```text
运行智能生成（N）
```

基本逻辑：

1. 按选中记录顺序逐行处理；
2. 每一行从左到右查找 AI 字段；
3. 跳过已有结果的 AI 单元格；
4. 跳过没有提示词的 AI 字段；
5. 文本等即时请求失败时，可能按原逻辑重试；
6. 图片和视频等付费媒体任务不会在上层盲目整体重提；
7. 当前行无法继续时，进入下一行。

## 16.2 为什么 AI 字段顺序重要

工作流从左到右执行，因此可以建立依赖链：

```text
基础信息 → AI 文案 → AI 提示词 → AI 图片 → AI 视频
```

例如“AI 图片”提示词引用“AI 提示词”字段时，必须把“AI 提示词”放在“AI 图片”左侧。

## 16.3 已有结果不会自动覆盖

工作流通常跳过已经有值的 AI 单元格。若要重新生成：

1. 先确认旧结果是否需要保留；
2. 清空目标 AI 单元格；
3. 再运行工作流。

智能图片和视频的单次生成可能把新结果追加到已有数组中。

## 16.4 整列生成的并发

大批量调用前确认：

- API 限频；
- 账户余额；
- 单次任务成本；
- 网络稳定性；
- OSS 容量；
- 输出目录空间。

付费媒体任务在弱网下最需要避免重复点击。

## 16.5 推荐分批策略

不要第一次就一次运行几百行。建议：

1. 先测试 1 行；
2. 再测试 3～5 行；
3. 确认字段引用、模型和保存路径；
4. 确认后台任务能够正常轮询、下载和写回；
5. 再按 20～50 行分批执行。

## 16.6 Job 阶段是什么意思

| 阶段 | 含义 |
|---|---|
| `preparing` | 创建本地任务记录 |
| `uploading` | 上传本地参考素材 |
| `creating` | 向模型服务商提交任务 |
| `submission_unknown` | 提交结果不确定，可能已扣费但没有拿到 task_id |
| `polling` | 已有 task_id，持续查询状态 |
| `generated` | 远端已经生成成功，等待或重试下载 |
| `downloading` | 正在下载到本地 |
| `completed` | 已下载完成 |
| `failed` | 某个阶段确认失败 |

## 16.7 Job 卡片常用操作

### 跳转原单元格

适合查找任务来源。目标行在另一个表格时，系统会先切换表格。

如果目标被筛选或折叠隐藏，会提示先清除筛选或展开分组。

### 写回原单元格

当任务已下载到本地，但结果没有自动写回时使用。

写回前会检查原表格、原记录、原字段是否仍存在，并避免重复添加同一文件。

### 继续轮询

只适合已经有 task_id 的任务。不要把 `submission_unknown` 当成普通轮询任务。

### 重试下载

适合远端已经生成成功，但本地下载失败的情况。重试下载不会重新生成媒体。

### 删除任务记录

垃圾桶删除的是本地 Job 记录，不保证取消远端任务。运行中的 Job 不建议删除。

## 16.8 Job 与单元格的关系

Job 单元格占位符是任务引用，不是图片 URL。

程序会在任务更新时：

- 更新单元格中的生成状态；
- 下载完成后移除 Job 占位；
- 写入最终本地文件；
- 使用统一路径规则避免重复添加同一结果。

## 16.9 Job Center 侧栏

点击“跳转原单元格”后，右侧 Job Center 不会自动关闭，方便连续排查多个任务。

## 16.10 弱网时的正确处理

- `polling` 暂时失败：等待程序自动继续；
- `generated` 下载失败：点击重试下载；
- `submission_unknown`：先查服务商后台，不要立即重新生成；
- OSS 上传失败：修复 OSS 或本地文件问题后重新发起；
- 401、403、400、模型名错误：属于配置问题，不要反复重试。

## 17.6 同图信息同步

## 17.7 参考图、评分和批注的数据一致性

v2.4.3 之后重点修复了以下问题：

- 从多图单元格点击某一张缩略图时，打开的就是实际点击的图片；
- 表格视图和图片审阅视图会读取当前最新参考图；

- 同一路径图片的评分和批注继续全局同步；
- `cropData` 取景信息仍保持单元格私有，不会强制同步到所有同路径图片。

# 19. 批量下载与本地归档

## 19.1 批量导出附件

选择包含附件、智能图片或智能视频的单元格，打开“批量导出附件”。

可按附件类型选择：

## 19.2 ZIP 下载

所有运行环境均可将选中的图片、视频或音频打包成 ZIP。适合临时交付和浏览器模式。

## 19.3 批量另存至本地

Electron 模式提供“批量另存至本地”，可直接将选中的图片、视频或音频写入指定文件夹，不需要逐个弹出保存窗口。

可使用字段组成路径。例如：

{货号}/{颜色}/{渠道}/{货号}_{颜色}_{渠道}
```

斜杠前的部分可形成子文件夹结构。

示例结果：

```

```text
商品图.png

商品图-2.png
```

```text

→ .part 临时文件
→ 下载完成
→ 原子改名为正式文件
→ 写回单元格
```

下载失败不会重新生成媒体。可在后台任务中心点击“重试下载”。

## 19.7 保存失败时检查

- 是否使用 Electron；
- 目录是否存在；
- 是否有写入权限；
- 路径是否包含非法字符；
- 文件名模板引用字段是否为空；
- 磁盘空间是否充足；
- 是否存在无法继续的旧 `.part`；
- Job 卡片中是否显示下载错误。

# 20. OSS 图床与容量管理

OSS 主要用于把本地参考图片转换为远程可访问 URL，供灵悟 AI 等云端模型使用。

## 20.1 需要填写的内容

v2.4.8 需要填写：

- Access Key ID；
- Access Key Secret；
- Endpoint；
- Bucket Name。

示例：

```text
Endpoint：https://oss-cn-beijing.aliyuncs.com
Bucket：threegunkids-你的名字
```

Domain 会自动生成，例如：

```text
https://threegunkids-你的名字.oss-cn-beijing.aliyuncs.com
```

Domain 输入框为只读，不需要手动复制旧域名。

> Endpoint 应填写区域级地址，不要填写已经带 Bucket 前缀的完整域名。

## 20.2 独立 Bucket 建议

推荐每位同事使用独立 Bucket。

好处：

- 容量分别计算；
- CSV 索引不会互相覆盖；
- 出错时容易判断任务属于谁；
- 清理旧素材时不会影响其他同事。

Job 卡片默认隐藏 Bucket。任务使用历史 Bucket，或发生 OSS 错误时才显示提示。

## 20.3 两套参考图目录

### 普通灵悟图片模型

```text
对象目录：references-node/日期/
本地 CSV：oss_references_node.csv
云端 CSV：references-node/oss_references_node.csv
格式：WebP Quality 90
```

### 灵悟 Gemini 图片模型

```text
对象目录：references-node-gemini-jpeg-v1/日期/
本地 CSV：oss_references_gemini_jpeg_node.csv
云端 CSV：references-node-gemini-jpeg-v1/oss_references_gemini_jpeg_node.csv
格式：JPEG Quality 95、4:4:4
```

## 20.4 哈希与复用

上传前会计算：

- SHA256：判断文件是否完全相同；
- dHash：普通 Profile 中用于判断视觉上相近的图片。

如果 CSV 中已有可用对象，程序可能直接复用旧 URL，减少重复上传。

Gemini JPEG Profile 当前更强调参考图质量和独立索引，不依赖普通 WebP 记录。

## 20.5 CSV 作用域与旧版升级

新版 CSV 额外记录：

```text
bucket
endpoint_host
reference_profile_id
```

用途：

- 判断 CSV 属于哪个 Bucket；
- 避免旧 Bucket 索引上传到新 Bucket；
- 区分普通 WebP 与 Gemini JPEG；
- 支持旧 10 列 CSV 升级到新版表头。

覆盖或清空本地 CSV 前会保留 `.bak`。

只有明确的 404 或 `NoSuchKey` 才会判断云端对象不存在。网络、权限和签名错误不会被当成“文件已删除”。

## 20.6 容量查看

打开：

```text
设置 → API 和模型配置 → OSS 图床配置
```

点击：

```text
刷新容量
```

可以查看当前 Bucket 用量、参考套餐容量、清理线、计划删除目录和预计清理后容量。

## 20.7 当前容量策略

```text
参考套餐容量：20 GB
自动清理触发线：19 GB
计划清理目标：17.5 GB
保护最近目录：3 天
管理目录：普通 WebP + Gemini JPEG
```

清理会按日期目录从旧到新处理，不会随机删除单个新文件。

## 20.8 自动检查与手动清理

容量检查会在以下时机触发：

- 本地参考素材上传完成后；
- 应用启动且环境变量中存在可用 OSS 配置时；
- 用户手动点击“刷新容量”。

当界面显示清理计划时，可以点击“强制清理”。

> 当前 `dryRun` 为关闭状态，“强制清理”和自动清理都可能真实删除 OSS 对象。操作前必须确认当前 Bucket 正确。

## 20.9 清理会删除哪些内容

清理对象主要是：

```text
references-node/YYYY-MM-DD/
references-node-gemini-jpeg-v1/YYYY-MM-DD/
```

最近 3 天的日期目录受到保护。

删除对象后，程序会尝试同步清理对应 CSV 记录。

## 20.10 权限建议

不要使用阿里云主账号永久密钥。建议创建 RAM 子账号，仅授予当前 Bucket 所需的查询、列举、上传、读取、删除和 CSV 同步权限。

## 20.11 OSS 常见错误

### AccessDenied

密钥没有 Bucket 权限，或 Bucket 策略不允许当前操作。

### NoSuchBucket

Bucket 名称、区域或 Endpoint 不匹配。

### Domain 显示异常

Endpoint 可能误填成带 Bucket 的完整域名。正确 Endpoint 例如：

```text
https://oss-cn-beijing.aliyuncs.com
```

### 上传成功但模型读取失败

检查 Bucket 或对象是否允许服务商读取。私有读对象不能直接用普通公网 URL 访问。

### 容量一直显示 0

可能是没有容量查询权限、网络或签名错误、当前 Bucket 配置错误，或容量查询失败后程序回退为 0。

### 出现“历史 Bucket”

说明该 Job 创建时使用的 Bucket 与当前设置不同。它主要用于排查旧任务，不代表当前任务一定出错。

# 23. 常见问题与排错

## 23.1 `npm ci` 安装失败

先查看错误末尾。

### `EAI_AGAIN`、无法连接 GitHub 或 Electron 下载失败

这是网络或 DNS 问题，不代表代码本身错误。处理方法：

1. 检查网络；
2. 切换稳定网络或正确配置代理；
3. 关闭终端后重新打开；
4. 删除未完成的 `node_modules`；
5. 再运行 `npm ci`。

```powershell
Remove-Item -Recurse -Force node_modules
npm ci
```

### 权限错误

不要在系统目录运行项目。移动到个人磁盘目录后重试。

## 23.2 执行 `npm run dev` 只有网页，没有 Electron 窗口

检查 Electron 是否安装成功、5173 端口是否被占用、终端是否有启动错误，以及是否误执行了 `npm run dev:react`。

v2.4.8 固定使用 5173 端口并启用严格端口模式，不会自动换到其他端口。

## 23.3 一直停在加载动画或界面空白

1. 查看终端错误；
2. 按 `Ctrl + Shift + I` 打开开发者工具；
3. 查看 Console 第一条红色错误；
4. 确认使用最终 v2.4.8 文件；
5. 重新执行 `npm install`；
6. 确认 Node.js 版本不要过旧。

## 23.4 保存后找不到文件

首次使用“保存”时注意系统文件选择窗口的目录。建议使用“另存为”明确指定位置。

## 23.5 自动备份无法开启

必须先保存工程。若工程尚无磁盘文件句柄，程序会提示先保存。

## 23.6 CSV 导入后字段类型都变成文本

这是当前设计。导入后手动将数字、附件、标签和 AI 列改成对应类型。

## 23.7 API 返回 401

API Key 无效、过期、没有余额或 Authorization 规则不匹配。

## 23.8 API 返回 404

通常是 Endpoint、接口基础路径或模型名称错误。

## 23.9 API 返回 429

请求过快、并发过高、额度不足或账户限频。创建付费媒体任务时遇到 429，先确认是否进入 `submission_unknown`。

## 23.10 文本生成正常，图片生成失败

文本和图片使用不同接口路径。检查图片提供商、图片模型名和 `/images/generations` 兼容性。

## 23.11 OpenAI 兼容接口文生图正常，参考图失败

部分接口不支持非标准 `base64Array`。改用支持该扩展的代理、Gemini Custom 或灵悟 AI。

## 23.12 Gemini 图片提示“不支持”

普通 Gemini Format 主要用于文本。图片生成请改用 Gemini Custom、OpenAI 兼容图像接口，或灵悟 Gemini 图片模型。

## 23.13 灵悟图片或视频提示必须在 Electron 中运行

退出浏览器模式后执行：

```powershell
npm run dev
```

## 23.14 灵悟无法读取本地图片

检查 OSS、本地文件、Endpoint、Bucket、自动生成的 Domain、RAM 权限和 Job 上传错误。

## 23.15 多参考图只传了一张

按第 14.7 节逐项检查。重点确认 v2.4.8、Electron、附件内部多图、模型上限和服务端能力。

## 23.16 视频时长与设置不一致

视频参数会按模型映射。例如 `grok-video-3` 只近似映射为 6 秒或 10 秒；Veo 3.1 会删除自定义时长。

## 23.17 批量工作流中某行后面的 AI 字段没有执行

检查前面的 AI 字段、提示词引用、后台 Job 是否尚未完成，以及后续字段是否依赖媒体结果。

## 23.18 生成结果被追加，没有覆盖旧图

需要替换时先清空单元格。

## 23.19 Photoshop 无法打开

检查完整 `.exe` 路径、Electron 模式和本地文件路径。

## 23.20 工程换电脑后 API 配置不见了

API 设置不在工程 JSON 中。使用“导出配置”迁移，并妥善保管密钥文件。

## 23.21 Job 一直显示 `polling`

查看网络、task_id 和服务商后台。可以点击“继续轮询”。超过约 30 分钟后，本地可能标为失败。

## 23.22 `submission_unknown` 是什么意思

表示请求可能到达服务器，但本地没有收到明确响应或 task_id。保留 Job，先查服务商后台和扣费记录，不要立即重复生成。

## 23.23 已经生成成功，但单元格没有结果

查看 Job 是否为 `generated` 或 `completed`。下载失败时重试下载；已有本地文件时点击“写回原单元格”。

## 23.24 跳转原单元格没有反应

确认当前打开的是原工程，原表格、记录和字段仍存在，并检查目标是否被筛选或折叠隐藏。

## 23.25 删除 Job 后远端任务还在运行

垃圾桶只保证删除本地记录，不保证取消远端任务。运行中的 Job 不建议删除。

## 23.26 下载后出现 `.part`

`.part` 是断点下载临时文件。网络恢复后在 Job Center 重试下载。

## 23.27 OSS 容量达到 19GB

确认当前 Bucket，刷新容量，查看计划删除目录，确认最近 3 天受保护后再执行清理。

## 23.28 Job 卡片为什么显示历史 Bucket

任务创建时使用的 Bucket 与当前设置不同，常见于更换员工 Bucket、共用电脑切换配置或查看旧 Job。

# 24. 数据安全与使用建议

## 24.1 不要只依赖本地缓存

至少保留正式工程文件、自动备份和关键节点版本副本。

## 24.2 API Key 属于敏感信息

不要截图公开、提交 GitHub、放入公共网盘或发送含密钥配置。

## 24.3 OSS 使用最小权限

使用 RAM 子账号，仅允许访问自己的 Bucket 和必要目录。

## 24.4 清理 OSS 前确认三件事

1. 当前 Bucket 名称正确；
2. 计划删除目录属于自己；
3. 最近仍在使用的参考素材已有本地备份。

## 24.5 不要随意删除运行中的 Job

Job 保存 task_id、阶段、原单元格位置、下载路径和恢复信息。删除后不一定能取消远端任务，反而可能失去自动下载和写回能力。

## 24.6 批量生成前估算成本

记录预计单价、生成数量、成功数、重试次数和成本。遇到 `submission_unknown` 不要重复提交。

## 24.7 建立稳定字段命名

字段改名会影响公式、提示词引用和任务来源理解。

## 24.8 先建立模板表，再复制

将常用字段、AI 配置、文件命名和工作流顺序做成模板表。
