# ComfyUI MiniMax H3 参数与路由

适用工程：AI Table Studio v2.6.3 后续分支  
最后核对：2026-08-24  
当前事实来源：两份 Manifest、四份 API 模板、`comfyui_client.js`

## 1. 模型与路由

### 首尾帧路由

```text
Manifest ID：minimax-h3-first-last-router
推荐前台名：minimax-h3-local
短别名：h3-fl
```

| 图片数 | 实际路由 |
|---:|---|
| 0 | 删除首帧加载与连接，执行文生视频 |
| 1 | 图片作为首帧 |
| 2 | 第一张作为首帧，第二张作为尾帧 |

该路由不接收参考视频或独立音频。

### 多参考路由

```text
Manifest ID：minimax-h3-reference-router
推荐前台名：minimax-h3-Ref-local
短别名：h3-ref
```

支持：

- 图片 0–9；
- 视频 0–3；
- 独立音频 0–3；
- 所有参考总数至少 1。

媒体按各自类型独立编号，Prompt 使用 `<Picture n> / <Video n> / <Audio n>`。

## 2. 模式

| 参数 | Fast | Quality |
|---|---|---|
| 步数 | 6 | 20 |
| Sampler | Euler | `res_multistep` |
| Turbo LoRA | 使用 | 不使用 |
| 推荐用途 | 测试和初筛 | 重要镜头 |

多参考 Fast 同时包含视觉参考与独立音频时，正式路由插入：

```text
H3TurboMixedReferenceFix
shared_reference_time = 1.0
```

该节点由 Hongs-node 提供，只调整 Conditioning 时间元数据，不修改原始素材、ComfyUI Core 或第三方 Turbo 插件。

## 3. 清晰度换算

前台清晰度档位表示目标短边。客户端结合当前画幅换算传给 `ResolutionSelector.megapixels` 的十进制 MP：

```text
目标 MP = 短边² ×（长边比例 ÷ 短边比例）÷ 1,000,000
```

| 比例 | 360P | 480P | 720P | 1080P |
|---|---:|---:|---:|---:|
| 1:1 | 0.1296 | 0.2304 | 0.5184 | 1.1664 |
| 2:3 / 3:2 | 0.1944 | 0.3456 | 0.7776 | 1.7496 |
| 3:4 / 4:3 | 0.1728 | 0.3072 | 0.6912 | 1.5552 |
| 9:16 / 16:9 | 0.2304 | 0.4096 | 0.9216 | 2.0736 |
| 21:9 | 0.3024 | 0.5376 | 1.2096 | 2.7216 |

也可以通过字段引用直接输入 `0.3`、`0.78MP` 等原始 MP；允许范围是 `0.1–16MP`。

## 4. ResolutionSelector 对齐

当前目录内四份 H3 API 模板均设置：

```text
ResolutionSelector.multiple = 32
```

因此理论短边和换算 MP 不保证最终宽高完全命中；实际尺寸还会受到节点的倍数对齐策略影响。测试报告必须记录 ffprobe 的真实宽高，不应只记录“选择了 720P”。

如果未来修改 `multiple`，必须同步核对：

1. 四份 API 模板；
2. 清晰度到 MP 的映射口径；
3. 8 种比例的真实输出尺寸；
4. 现有字段引用的兼容性；
5. 本文映射表与测试基线。

## 5. 比例、时长和声音

支持比例：

```text
1:1  2:3  3:2  3:4  4:3  9:16  16:9  21:9
```

支持时长：

```text
3  5  8  10  15 秒
```

声音默认关闭。关闭时，提交前删除 `CreateVideo.audio` 连接；打开时保留模型音频链路。参考视频的内嵌音轨目前不重复注入独立音频端口，以避免 Turbo 条件形状冲突。

## 6. 字段引用

清晰度、比例、时长、模式和模型均可由表格字段引用，例如：

```text
模型：{H3模型}
清晰度：{清晰度}
比例：{画幅}
时长：{时长}
模式：{生成模式}
```

建议使用单选标签字段约束取值，避免自由文本拼写不一致。Agent 配置 AI Video 字段时使用 `field.configure_ai`，不要直接 patch 内部 `aiVideoConfig`。

## 7. 推荐测试矩阵

先固定：3 秒、360P、Fast、声音关闭、固定 Seed。

最小路由覆盖：

1. 0 图文生。
2. 1 图首帧。
3. 2 图首尾帧。
4. 1 图 + 1 音频多参考 Fast。
5. 1 视频 + 1 音频多参考 Fast。
6. 1 图 + 1 视频 + 1 音频多参考 Fast。
7. 一条相同素材的 Quality 对照。

协议测试验证路由结构；真实生成才验证显存、模型、实际尺寸和输出质量。

## 8. 当前边界

- 高分辨率与长时长会显著增加显存、时间和失败风险。
- 连续多个视频参考重负载任务后可能出现底层模型/显存故障；应停止继续排队并干净重启 ComfyUI。
- Hongs-node 修复的是 Fast 混合 Conditioning 形状问题，不解决所有显存或模型加载错误。
- 新增比例或清晰度时必须更新 Manifest、测试与文档，不能只改前台下拉框。
