## 3. `standard` 到底是什么

这里有三套名称，不能混用：

| 层次 | 值 | 含义 |
| --- | --- | --- |
| UI/用户输入 | `auto` / `high` | 当前对外展示的生成模式 |
| 兼容归一化值 | `standard` / `enhanced` | 分别对应 auto/high，供旧配置、字段引用和内部逻辑兼容 |
| ComfyUI 通用模板槽位 | `fast` / `quality` | 既有工作流注册器的模板键；Qwen 两个键都指向同一个 `image_api.json` |

Qwen 测试表中的 `standard` 是早期测试数据保存的内部值，等价于 UI 的 `auto`，不是第三种模式，不是新的权重，也不代表额外加速。旧表出现该值可以继续运行。当前 Qwen 的 `high/enhanced` 仅预留未来版本，**不会切换到另一套模型**；实际画质变化由独立的 quality 步数控制。

权重中的 `qwen3vl_8b` 明确指文本/视觉编码器文件；不能仅依据这个文件名推断整套图像生成模型的参数规模。所谓未来16B入口在本次没有实现或验证。

## 4. 智能图片调用链与完整参数映射

### 4.1 前台到后台

```text
智能图片列配置 / 单元格字段引用
  → Grid.tsx 解析模型、提示词、参考图、分辨率、比例、模式、画质
  → 选择 provider
    ├─ lingwu → generate-lingwu-image IPC
    │           → MediaJobRunner.createImageJob
    │           → 参考图上传/准备
    │           → buildLingwuImageParams（按准确模型名映射）
    │           → LingwuClient POST /v1/media/generate
    │           → task_id / Job / 轮询 / 下载 / 单元格回填
    ├─ comfyui → 同一 Job 基础设施 → ComfyUIClient 图片路由
    ├─ gemini-custom → 前台 Gemini 协议请求
    └─ openai → 前台既有 OpenAI-compatible 图片请求
```

UI 模式和画质保存于 `aiImageConfig.mode/quality`，允许 `{字段名}`。旧配置不需要迁移数据文件。中文历史选项和 standard/enhanced 兼容。图片列的数量仍按每张图单独创建请求/Job；不新增多图批次协议。

### 4.2 Lingwu Format 当前模型清单

以下新参数均位于请求体的 **params 内**；请求外层保留 `{model,prompt,params,count}`，模型名原样发送。

| 模型 | 模式 auto/high | 画质 auto/high/max | 尺寸与比例 | 参考图 |
| --- | --- | --- | --- | --- |
| `tt-image-2.5` | `version: flare/sunburst` | `quality: auto/high/max` | **沿用原有 imageSize+aspectRatio→size 换算** | 普通 WebP q90 路径 |
| `gemini-3.1-flash-image-preview`（Nano 2） | `thinkingLevel: minimal/high` | 不发送独立 quality | `imageSize: 0.5K/1K/2K/4K`，`aspectRatio` | Gemini JPEG q95 路径，Profile 上限14 |
| `gemini-3-pro-image-preview` | 明确设置时透传 `mode: auto/high` | 明确设置时透传 quality | 原 `imageSize: 1K/2K/4K` + `aspectRatio` | Gemini JPEG q95 路径 |
| `doubao-seedream-5-0-260128` | 明确设置时透传 | 明确设置时透传 | `size: 2K/3K` + `aspect_ratio`；0.5/1/2K→2K，3/4K→3K | 普通 WebP q90 路径 |
| `gpt-image-2`、`gpt-image-2-guan`、其他无专属 Profile 的模型 | 明确设置时透传 | 明确设置时透传 | 原有精确/近似 size 换算 | 普通 WebP q90 路径 |

TT 的 `-flare/-sunburst` 后缀也识别；未显式设置 mode 时保留后缀版本。Nano 2 不改名成文档示例中的 `banana-2`。参考图压缩 q90/q95 与生成 quality 不同，不能混为一谈。

**兼容原则：**旧表缺少 mode/quality 时，TT 默认 flare/auto，Nano 2 默认 minimal；其他模型不额外注入这两个字段。用户主动设置时，其他模型按要求透传；透传不等于渠道保证识别或执行，需通过手动出图判断。

**已核对的最终请求示例：**

```json
{
  "model": "tt-image-2.5",
  "prompt": "...",
  "params": {"size": "1024x1024", "version": "sunburst", "quality": "max"},
  "count": 1
}
```

```json
{
  "model": "gemini-3.1-flash-image-preview",
  "prompt": "...",
  "params": {"imageSize": "1K", "aspectRatio": "1:1", "thinkingLevel": "high"},
  "count": 1
}
```

Nano 2 没有 quality 是正确行为；没有 thinkingLevel 才表示模式未进入最终请求。TT 的新 version/quality 和 Nano 2 thinkingLevel 已依据用户提供的灵晤接入文档核对。TT 新尺寸协议曾评估，最终按用户要求撤回，**未保留新的尺寸改写、同步编辑端点或 multipart 分支**。

## 5. Qwen 工作流结构与行为

模型入口：`qwen-image-2.1-local`、`qwen-image-2.1-transparent-local`。工作流 ID：`qwen-image-2.1`，mediaType 为 image。

- **无参考图：**原生 EmptyLatentImage 动态设置宽高 → KSampler，提示词由 TextEncodeQwenImage21 编码。ComfyUI 原生采样入口适配空 latent 的通道/空间压缩率。
- **1–5 张参考图：**为每张图创建 LoadImage，依次连接 `images.image_1...`；默认使用 TextEncodeQwenImage21 的 latent 输出并跟随第一张参考图。若明确填写比例字段，则改为创建 `EmptyLatentImage` 覆盖 `KSampler.latent_image`。空引用跳过，不补齐。
- **透明入口：**同一权重、同一模板，自动包装 RGBA/透明背景提示词；原生 VAE + SaveImage 保存 PNG。透明效果取决于生成内容，不能承诺所有提示词边缘都完美。
- **画质：**auto/high/max → 25/30/40 步；Euler、Simple、CFG 1、denoise 1。模式 high 不改变当前权重。
- **PNG 回填：**修复 ComfyUI `/view?filename=...png` 查询参数路径的扩展名识别，避免下载为 JPG；保持 PNG 字节和 alpha。
- **边界防护：**图片不能误走视频工作流；节点健康检查核对真实 object_info 内容，HTTP 200 空对象仍报告缺节点。

### 5.1 分辨率计算

数字 `0.5/1/1.5/2` 是 K 系数，**不是裸 MP**。目标基准 resolution = 系数×1024，按32像素对齐；范围0.5–2。旧 `1024x1024` 配置兼容1K，4K拒绝。

设首图宽高比为 r，目标宽高约为：

```text
w = round(resolution × sqrt(r) / 32) × 32
h = round(resolution / sqrt(r) / 32) × 32
```

方图1K=1024²≈1.05MP；2K=2048²≈4.19MP。2K为面积等级，非长边2048硬上限。非方图因32对齐会存在比例偏差。图生图的参考图在编码前同样按目标面积缩放，不采用 resolution=0 的原尺寸路径。

文生图可用比例字段；图生图**未填写比例字段**时继续跟随首图，包括比例下拉选择“自动（图生图跟随首图）”的情况。图生图**明确填写比例字段**时，会创建自定义 `EmptyLatentImage` 作为采样画布，从而覆盖首图比例。这样既保留了旧的首图跟随机制，也支持官方 custom size 的比例控制。

## 2026-09-26 局部修图比例规则修复（v2.7.2b 维护补丁）

上文 v2.7.2 / v2.7.2b 的比例规则专指**普通图生图**。局部修图是更高优先级的独立模式：原始图片第一张的已保存裁切比例优先；无裁切数据时从第一张图的实际宽高读取比例。即使表格比例选了 `9:16` 或“自动”，局部修图也不会绕开原图裁切比例。Qwen 的 `EmptyLatentImage` 节点 90 支持接收这一显式比例，后台据此计算目标宽高并切换采样 latent；源图优先接 `images.image_1`。普通 Qwen 图生图的自动/显式比例行为不变；其他 Provider 原有 `cropData.ratio` 覆盖规则仍保留。

协议模拟测试已覆盖 Qwen `EmptyLatentImage` 显式宽高及首图引用顺序；是否与本机 ComfyUI 实际生成结果完全一致仍需本机出图验收。
