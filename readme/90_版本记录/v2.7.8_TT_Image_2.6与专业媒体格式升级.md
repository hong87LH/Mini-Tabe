# v2.7.8 TT Image 2.6 与专业媒体格式升级

产品版本：v2.7.8
Action API：v0.1 / phase4.7
Action Definition：1.4
日期：2026-11-08

## 1. TT Image 2.6

- 在不改变 TT Image 2.5 旧配置、旧任务和尺寸换算的前提下，新增平级 `tt-image-2.6` 路由。
- 继续使用简化的模式 `auto/high` 与画质 `auto/high/max`；新增复杂度 `low/medium/high`，字段引用兼容中文“低/中/高”。
- 默认输出 PNG，可选 SVG 或 GIF。GIF 模式展开帧数与单帧时长，并按接口约束忽略分辨率、比例。
- `tt-image-2.6-guan` 作为独立渠道别名登记，支持 PNG/JPEG/WebP/GIF，不向其发送 SVG。
- TT Image 2.5 同步识别 `-token`、`-flare-token`、`-sunburst-token` 渠道别名。

## 2. 结果接收与文件格式

- 下载器不再假设请求格式就是实际格式，而是读取文件签名识别 PNG、JPEG、WebP、GIF、SVG。
- 渠道返回与请求格式不一致时正常接收，并将最终扩展名、MIME 和 Job 的 `actualFormat` 修正为真实值。
- GIF 与 SVG 不进入普通位图缩放；GIF 使用动画校验，SVG 使用轻量结构校验。

## 3. 附件、预览与外部应用

- 表格附件支持拖拽和选择 `.gif`、`.svg`、`.ai`、`.pdf`、`.psd`、`.psb`。
- GIF 保留轻量格式角标：表格内位于右下，图片审阅位于左上，避开右上处理状态。
- PSD/PSB/AI/PDF/SVG 使用浅灰底文件类型图标，不重复叠加角标；Photoshop 类使用蓝色标识，矢量类使用橙色标识。
- SVG、PDF 支持内置大图预览；PSD、PSB、AI 直接交给已配置的专业应用。
- 专业格式独立检查本地文件状态；文件确实不存在时显示灰化开裂图标，文件存在但没有缩略图不会被误判为丢失。
- 本地应用设置新增矢量应用路径。位图、GIF、PSD、PSB 使用 Photoshop 路径；SVG、AI、PDF 使用矢量应用路径（建议 Illustrator）。

## 4. Action API

- `field.configure_ai` 新增 `complexity`、`outputFormat`、`frameCount`、`frameDurationMs`，全部支持字段引用。
- `generation.preview` 返回解析后的复杂度、格式及 GIF 参数；不支持的模型/格式组合以 `IMAGE_PARAMETER_INVALID` 阻断，不产生费用。
- `generation.get_capabilities` 新增 `lingwuImageProfiles`，列出模型别名、格式和参数能力，供 Agent 以运行时能力为准调用。
- HTTP Schema 已由 Action Definition 1.4 重新生成，协议版本和 phase 保持不变。

## 5. 兼容性

- 未配置新字段的旧表继续使用原默认值；非 TT 2.6 模型不会获得新增请求参数。
- v2.7.7 的 Qwen、ComfyUI、LoRA、TT 2.5 和既有 Job 数据结构保持兼容。
- 外部应用调用保留旧 `open-in-photoshop` IPC，同时新增通用应用打开接口。

## 6. 验证

- TypeScript：`tsc --noEmit` 通过。
- Vite 生产构建通过。
- 新增文件签名和专业媒体类型测试通过。
- UI 工作流 47 项通过。
- TT 2.6 参数映射、中文别名、GIF 去尺寸、官转禁用 SVG 均有自动测试覆盖。

## 7. 交互复核修订

- 输出格式说明压缩为单行“格式：PNG”，减少设置面板高度。
- GIF 保留格式角标；表格内位于右下，审阅视图移至左上，避免与右上处理状态冲突。
- PSD/PSB/AI/PDF/SVG 取消重复角标，改为更大的中心格式文字；PSD/PSB 使用更深的蓝色背景。
- SVG 恢复内置大图预览，PDF 使用 Chromium PDF 预览；PSD/PSB/AI 仍直接交给已配置应用。
- 外部应用启动改为独立进程成功拉起即返回，避免 Photoshop/Illustrator 长驻进程造成 IPC 长时间等待，并保留旧 Photoshop 接口回退。

后续实机复核发现 Adobe 冷启动不适合 detached 进程：可能只显示工具栏而没有正常主窗口。最终实现改为普通 GUI 子进程，收到系统启动事件后立即返回，不再改变 Adobe 的窗口归属。专业格式占位改用用户提供的 32px / 96px 两套文件图标：表格（含紧凑行高）使用 32px，审阅模式使用 96px；容器统一为极浅灰底。

专业格式图标随后按显示场景细化：紧凑行高保持小尺寸，中等行高适度放大，宽松/极宽行高、附件展开面板和审阅视图使用 96px 资源并提高容器占比。PSD/PSB/AI/PDF/SVG 的本地路径增加独立文件存在性检测；文件存在但系统无缩略图时继续显示正常类型图标，只有路径文件确实不存在时才显示灰化破裂状态。Action Schema 已重新生成并核对一致，Action API 62/62、Generation Preview 12/12、缩略图 10/10、UI 工作流 47/47 全部通过。

丢失文件的破裂视觉进一步改为与容器同底色的窄折线挖空，裂缝严格限制在文件图标自身范围内，顶部和底部与文件轮廓对齐；左右分别使用与文件外框同级的浅灰色开放描边，使文件轮廓和格式文字呈现自然断裂感。表格与图片审阅的“刷新可视区域媒体缩略图”统一扩展到专业格式：普通媒体重新获取系统缩略图，PSD/PSB/AI/PDF/SVG 则重新检查文件存在状态；两类任务分别统计，专业格式不会再被误报为缩略图刷新失败，文件恢复后可直接刷新回正常图标。
