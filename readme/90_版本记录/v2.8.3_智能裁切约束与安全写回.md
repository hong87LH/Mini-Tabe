# AI Table Studio v2.8.3 升级说明

发布日期：2026-11-26

升级基线：v2.8.0

主题：双模型智能裁切、明确约束语义与安全批量写回

## 正式能力

v2.8.3 保留 v2.8.0 已发布的 Qwen 人物功能 LoRA、即梦 5.5、MiniMax H3 图像与普通位图统一 PNG 规则。本版把后续智能裁切迭代收口为一个正式稳定版本，中间已被替代的试验方案不再作为升级步骤重复描述。

- 智能裁切完整内置在表格工程中，不调用外部 HTML 工作台；
- `PoseLandmarker Full` 提供人物身份与肩、胯、膝、踝等姿态锚点；
- 独立 `ImageSegmenter` 提供真实发顶、头发左右边缘、人物和服装轮廓；
- 紧凑头像优先完整保留头发与最低顶部安全线；
- 通用人体裁切支持固定比例与近似比例，并可保护宽摆服装等骨骼之外的语义轮廓；
- 姿态和轮廓分别缓存到 IndexedDB；模型与 WASM 使用 Electron/Chromium HTTP Cache；
- 右键菜单与 Agent Action 共用 `public/smart_crop/presets.json`。

## 约束语义

- `framing` 是期望景别，属于软构图目标；
- `protection` 是必须完整包含的内容范围，属于硬约束，但不是裁切框的起止边缘；
- 固定比例可在硬范围外保留额外画面，不能裁掉硬范围；
- Preview 返回 `constraintContract` 与 `constraintResolution`，其中包含硬保护矩形、最终裁切框、扩展像素和警告；
- 原图边界或固定比例导致硬范围无法完整容纳时返回 `PROTECTION_CLIPPED`，不写入错误裁切。

## Agent 与批量可靠性

- 推荐顺序保持为 `media.list_crop_presets → media.smart_crop_preview → media.smart_crop_apply`；
- `overrides` 只影响本次请求，不修改共享预设；
- 同一 `idempotencyKey` 的执行中请求会合并，避免超时重试形成重复写入；
- 识别完成后按媒体稳定身份在最新 Cell 中重新定位，不再用旧数组索引覆盖整个单元格；
- 识别期间图片被删除、替换或出现无法唯一判断的重复来源时返回 `MEDIA_CHANGED`；
- 空目标、越界索引、非位图媒体和求解失败分别进入稳定的 `skipped[]` / `failed[]`；
- 下半身起点使用锚点上缘、终点使用锚点下缘，`above_knee` 与 `knee` 保持可区分；
- Action Definition 固定为 `1.9.1`，协议继续为 `v0.1 / phase4.7`。

## 正式边界

正式版不包含后续已经回退的手部剔除、`lower_garment` 下装专用轮廓模式或批内首张分割失败后禁用后续分割等试验策略。每张图片仍独立尝试轮廓识别，失败时仅该图退回骨骼方案。
