# AI Table Studio v2.8.3 发布说明与同事邮件

发布日期：2026-11-26

升级基线：v2.8.0

发布主题：双模型智能裁切、明确约束语义与安全批量写回

## Git Release 文案

AI Table Studio v2.8.3 以 v2.8.0 为同事升级基线。v2.8.0 已包含 Qwen 人物功能 LoRA、即梦 5.5、MiniMax H3 图像与普通位图统一 PNG；本次发布只概括最终有效的新能力，不重复中间已被覆盖或回退的实现。

本版把双模型智能裁切正式纳入表格媒体工作流：PoseLandmarker 负责人物身份与身体锚点，ImageSegmenter 负责真实发顶、头发边缘、人物和服装轮廓。紧凑头像优先保全头发和顶部安全线；服装与下装裁切结合骨骼纵向锚点和语义横向轮廓，并支持固定比例与近似比例。

裁切契约现已明确：`framing` 是可放宽的期望景别，`protection` 是必须完整包含的硬范围，但不是裁切框边缘。Preview 会返回硬保护矩形、最终裁切框、比例扩展和警告；写入前再次核验硬范围，无法完整容纳时返回 `PROTECTION_CLIPPED`，不会静默写入不完整结果。

Agent 批量操作增加执行中幂等合并与媒体身份安全写回。同一请求超时重试可复用原 `idempotencyKey`；识别期间图片被替换、删除或无法唯一定位时返回 `MEDIA_CHANGED`。下半身锚点与错误分类同步收口，Preview 与 Apply 使用相同求解结果语义。Action Definition 为 1.9.1，协议仍为 v0.1 / phase4.7。

姿态和轮廓分别缓存到 IndexedDB；模型与 MediaPipe WASM 通过 HTTPS 加载并使用 Electron/Chromium HTTP Cache。首次使用需要联网，后续同图切换预设复用识别结果。Electron 运行时与依赖锁定为 41.3.0。

## 同事邮件正文

主题：AI Table Studio v2.8.3 更新（基于 v2.8.0）——智能裁切与批量可靠性增强

各位同事：

AI Table Studio 已从 v2.8.0 升级到 v2.8.3。原有 Qwen 人物 LoRA、即梦 5.5、MiniMax H3 图像和 PNG 输出规则全部保留；本次主要增加表格内置智能裁切，并完善 Agent 批量操作的预览与安全写回。

主要变化：

1. 头像裁切会识别真实发顶和头发边缘，优先完整保留头发与顶部安全线；
2. 上衣、短裙、裤装等任务结合人体关键点和服装轮廓，支持固定比例和近似比例；
3. 在图片列选中单格、多格或多行后，可从右键“智能裁切”二级菜单直接批量处理；
4. Agent 可先预览每张图的硬保护范围、最终裁切框和覆盖风险，再确认写入；
5. 识别期间如果图片被替换或删除，系统会拒绝旧结果写回，避免覆盖错图；
6. 模型首次使用需要联网，之后由系统缓存；同一图片切换预设会复用识别结果。

升级建议：

1. 先保存并备份当前 `.aistudio.json` 工程；
2. 解压附件中的 v2.8.3 精简工程到新目录，不要直接覆盖正在使用的旧目录；
3. 复用团队已有依赖时确认 Electron 为 41.3.0；否则在新目录执行 `npm ci`；
4. 运行 `npm run dev`；
5. 第一次使用智能裁切时保持联网，等待姿态、轮廓模型和 WASM 初始化完成；
6. 先用 1–2 张真人图验收头像和一种服装预设，再开始批量处理。

附件包括：

- v2.8.3 精简工程 ZIP（不含 `node_modules`、FFmpeg 可执行文件、个人 CSV 和本机配置）；
- v2.8.3 完整使用指南 HTML（可离线打开和全文搜索）。

旧 v2.8.0 表格无需转换。智能裁切的使用方法、参数含义、模型缓存、预设维护和 Agent 临时参数均已按原完整指南章节结构更新。
