## 3. 分阶段升级内容

### Phase 1：表格基础控制

- 读取系统能力、当前上下文、表格列表和字段 Schema。
- 创建表、字段和记录。
- 更新字段、调整字段顺序。
- 查询/读取记录。
- 单 Cell 与批量 Cell 写入。
- 支持 Dry Run、确认门和 UI Undo 链路。
- Main 与 Renderer 双层串行队列，并在 React commit 后再返回 HTTP 成功，解决快速连续写入丢失更新。

### Phase 2：Media Instance

- 读取图片、视频、音频的真实持久化实例。
- 保留图片 `cropData` 与音视频 `trimData`。
- 新媒体通过 `media.attach` 添加；已有编辑实例通过 `media.copy_instance` 复制。
- 按行列举媒体，并解析 AI 字段真正使用的有效媒体上下文及顺序。
- 禁止通过 Attach 直接伪造 Crop/Trim，也不持久化预览临时字段。

### Phase 3：Generation 与 Job Center

- `generation.preview` 在不产生费用的情况下解析 Prompt、媒体和阻塞原因。
- `generation.run` 复用现有 Grid 生成 Runtime，不让 Agent 直接调用 Provider。
- AI Text、AI Image、AI Video 继续沿用 UI 已验证的 Provider/Job 链路。
- `job.list/get/retry/cancel` 提供安全任务管理。
- 生成使用幂等键，避免相同请求重复付费。
- Retry 只恢复已有 `taskId` 的轮询或已有 `resultUrl` 的下载，不自动重新付费提交。

### Phase 3.5：高频 UI 协作

- 读取活动 Cell、Selection、当前可见行列。
- `table.activate` 等待目标 Grid Runtime Ready 后再 ACK。
- 读取/更新 Filter、Sort、Group 语义视图。
- `row.query` 支持当前视图、OR、排序、指定 Row、公式结果。
- 复制字段、安全配置 AI Text/Image/Video。
- 管理单选/多选 Options。
- 读取、建立和解除 Cell Link。
- 查询非敏感 Provider/Model 能力。
- Preview 扩展到最终模型、凭据可用性、媒体 Crop/Trim、视频参数、输出路径与费用可能性。

### Phase 4：协作一致性与安全

- 所有响应携带单调递增的 `workspaceRevision`。
- Mutation 支持 `expectedRevision`；旧快照写入返回 `STALE_WORKSPACE`。
- `transaction.preview/execute` 提供原子多步修改，失败零落盘。
- API Undo/Redo 使用 `undoToken`，并拒绝覆盖用户后续的新编辑。
- 所有 Mutation 支持通用 `idempotencyKey`。
- HTTP 入口增加 AJV Schema 校验、权限、Token TTL、Actor 与 Audit Log。
- 权限细分为读取、数据写入、Schema、媒体、生成、导出、保存和破坏性操作。

### Phase 4.1：完整编辑

- 表：更新、复制、删除、重排。
- 字段：删除、类型转换预览与执行。
- 行：插入、复制、删除、重排。
- Cell：清空、范围复制、填充。
- 媒体：移除、移动、重排、Crop、Trim、Rating。
- Job：读取结果、绑定结果、删除历史。
- Crop 与 Trim 使用受约束的语义参数，不开放任意内部 JSON 注入。

### Phase 4.5：长任务与交付

- SSE 事件：`workspace.changed`、`job.updated`、`generation.completed`、`batch.completed`。
- Batch：列表、详情、取消、仅重试失败项、结果列表。
- Export：预览、附件、CSV、JSON。
- Workspace：Dirty State 与已绑定工程保存。
- Batch 复用现有 Network Job Store；Export 复用现有 Electron 文件通道。

### Phase 4.6：可发现 Action 与 MCP 前置适配

- 新增 `agent_api/action_definitions.js`，集中维护 Action 参数 Schema、权限、写入属性、确认要求、说明和示例。
- 新增 `system.describe_action`，Agent 可以在执行前按 Action 获取精确、机器可读的定义。
- HTTP JSON Schema 改为从 Action Definition 生成，避免服务端校验、CLI 帮助和未来 MCP Tool Schema 各维护一份。
- CLI 增加 `<action> --help`、`--params-file`、`--request-file`、`--stdin`、`--validate-only` 和脱敏 `--print-request`。
- 复杂中文、Windows 路径与嵌套 JSON 可直接走 UTF-8 文件或 stdin，降低命令行转义错误。
- 生成预览对已配置但当前行为空的媒体引用采用“跳过空引用并告警”；是否允许零参考由用户选中的 Workflow 输入约束决定，不自动切换模型或 Workflow。

### Phase 4.7：高频响应裁剪与失联 Job 专项清理

- `system.get_capabilities` 默认返回紧凑 Action 名称列表，需要完整元数据时使用 `detail=full`。
- `job.list` 支持 `summary/full` 和 `fields` 精确投影，减少日常 Job 轮询的无关输出与 Token 消耗。
- `job.cleanup_stale.preview / job.cleanup_stale` 只处理超过阈值、具有 `taskId`、且经 ComfyUI Queue/History 证明远端任务已经缺失的非终态 Job。
- 成功、失败、取消、已有结果、真正运行/排队、远端不可达或状态未知的 Job 始终保护；清理不删除结果文件。
- 清理会同步移除 Cell 中精确匹配 `jobId` 的 `networkJob` 占位，并保留同 Cell 的完成媒体与其他任务。
- CLI 对 Windows 旧式 `--params` 的常见引号损坏做安全恢复，不执行任意代码；新增 `--select` 裁剪响应分支。

## 5. 安全与协作约束

- 服务默认关闭，只在显式开启后监听 `127.0.0.1`。
- Action 与 Events 需要 Bearer Token；Health 不需要 Token。
- 可设置权限、Token TTL、Actor ID/Name。
- Audit Log 位于 Electron `userData/table-action-api-audit.jsonl`，不记录 Token、API Key 或 Provider 凭据。
- 破坏性、覆盖式、保存、导出与生成等操作使用确认门。
- 并发 HTTP 请求和 Renderer Action 都会串行，成功 ACK 发生在 React commit 之后。
- API 不开放 Provider Key、OSS Secret、任意 Shell/JavaScript 或 OSS 清理。

## 9. MCP 前置结论

下一阶段 MCP Server 应保持轻薄：

```text
Action Definition
  → MCP Tool Schema
  → localhost Table Action API v0.1
  → 现有权限 / Revision / Transaction / Undo / Generation / Job
```

MCP 层只负责 Tool 发现、参数转换、会话接入和面向 Agent 的错误表达，不重复实现参数定义、表格状态、媒体实例、生成和 Job 逻辑。这样 HTTP API 继续服务脚本与自动化，MCP 服务 Codex/其他 Agent，两者共享同一套 Action Definition 与业务事实来源。
