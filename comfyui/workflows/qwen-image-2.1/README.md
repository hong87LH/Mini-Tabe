# Qwen Image 2.1 本地图片工作流

本工作流属于**图片生成**，不属于 MiniMax 视频生成。一个 API 模板按实际引用数量路由：0 张文生图，1–5 张图生图；空引用跳过、不补齐、不复制参考图。5 张是本工程依据本机报告设置的运行上限，不代表模型理论上限。

## 安装与版本

- 已验证 ComfyUI **0.37.0**，前端 1.52.7，workflow templates 0.11.66。使用此版本或兼容更新版本；这些是验证版本，不声称是最低版本。
- 只用 ComfyUI 原生节点，无需 MiniMax Turbo、Hongs-node 或第三方抠图插件。
- 必须具有 `TextEncodeQwenImage21`、`QwenImage21Cache`、`EmptyLatentImage` 及常规加载/采样/保存节点。健康检查会检查 object_info 的实际节点内容，HTTP 200 空对象也算缺失。
- 模型由使用者下载，不随 Git 分发：

| ComfyUI 目录 | 文件 |
| --- | --- |
| models/diffusion_models | qwen_image_2.1_int8_convrot.safetensors |
| models/text_encoders | qwen3vl_8b_int8_convrot.safetensors |
| models/vae | qwen_image_2.1_vae_bf16.safetensors |

模型放子目录时须同步修改 `image_api.json` 对应文件名。更新后重启 ComfyUI。采用本机报告的 Python 3.13.14 / PyTorch 2.13.0+cu130 / RTX 4060 Laptop 8GB 组合验证，不要求其他安装者照搬所有版本。

官方来源：[ComfyUI](https://github.com/Comfy-Org/ComfyUI)、[模型与用法](https://github.com/QwenLM/Qwen-Image-2.1)、[ComfyUI 模型权重](https://huggingface.co/Comfy-Org/Qwen-Image-2.1)、[官方工作流](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_t2i.json)。

## 表格使用

1. 启动装有上述权重的 ComfyUI。表格“API 和模型配置 → 图片”自带 `ComfyUI 本地 Qwen Image 2.1`，端点默认 `http://127.0.0.1:8188`，无需 Key。
2. 智能图片列“图片生成模型”选 `qwen-image-2.1-local`；透明图选 `qwen-image-2.1-transparent-local`。两者共用同一模板。已有云端图片默认模型不被替换。
3. 无图片引用即文生图；在“原始图片”引用 `{商品图} {风格图}` 可图生图。明确提示词里第一张、第二张图片的作用；单元格里多张图片按传入顺序成为独立参考。
4. 分辨率选 0.5K / 1K / 1.5K / 2K，或引用字段（例如 `{分辨率}`），单元格写 `0.5`、`1.5`、`2` 或带 K 写法。数值是 K 系数：resolution = 系数 × 1024，32 对齐，范围 0.5–2；不采用 H3 的裸 MP 单位。超出范围会报错，不静默升到 4K。
5. 文生图使用比例字段；图生图若明确填写比例字段，则用 EmptyLatentImage 覆盖采样画布并按该比例生成；未填写比例字段时，继续按第一张参考图原始比例生成。

2K 表示约 2048² 像素的面积等级，不是长边限制。方图 0.5/1/1.5/2K 分别为 512/1024/1536/2048；其他比例宽高按面积计算并 32 对齐。参考图在进入编码器前按同一等级等比缩放，始终不使用 resolution=0 的原尺寸路径。

透明模型自动加入本机报告已验证的 RGBA 提示包装；请描述独立主体，避免同时要求白底、地板等不透明场景。输出由原生 VAE + SaveImage 保存 PNG，并在下载和表格回填中保留 PNG 扩展名与 alpha；透明度仍取决于生成结果，不承诺每条提示都能产生完美透明背景。


## 局部修图与普通图生图的比例优先级（2026-09-26 修复）

- **局部修图（开启“引用裁切数据”）优先级最高：**以“原始图片”引用的**第一张实际图片**为准。存在保存的 `cropData.ratio` 时，使用它对应的取景框比例；没有 `cropData` 时，读取这张原始图片的宽高比例；与旧策略一致，比例归一化到原工程支持的最近标准比例，不采纳比例下拉框或引用字段中与之冲突的比例。
- **Qwen 兼容：**局部修图得出的比例会作为显式 `aspectRatio` 传入本地 Client，`KSampler.latent_image` 改接 `image_api.json` 内置的 `EmptyLatentImage`（节点 90），宽高依 K 系数和源图比例计算；编辑源图优先接入 `images.image_1`。这不同于普通图生图“自动”模式不传比例、沿用原生 latent 的逻辑。
- **普通图生图（未开启局部修图）：**比例自动/空值时跟随首图；明确设置 `1:1` / `3:4` / `9:16` 等时按自定义 latent 控制画布。**文生图**仍按具体比例建立空 latent（自动默认 1:1）。
- 其他图片 Provider 的历史局部修图 `cropData.ratio` 覆盖比例规则保留；没有裁切信息时补充读取第一张原图的实际比例。保存后还原实际裁切区域尺寸（`scaleToSource`）是独立设置，不等同于采样画布尺寸。
- 如果有多个来源，不能因为第一张没有 `cropData` 就误取第二张图片的裁切比例；Qwen 局部修图中“原始图片”来源排在提示词附带的辅助参考图之前。

## 性能与实现

画质 auto / high / max 分别为 25 / 30 / 40 步；Euler / Simple、CFG 1、denoise 1。生成模式 UI 为 auto/high，内部兼容 standard/enhanced；high 是未来版本预留，目前仍执行已安装的同一模型，不虚构版本切换。不套用视频 6 步 Turbo。报告中低步数有空白/重影，所以不以 2/4 步作为正式生成默认。

本机报告：1K 25 步文生图约 32 秒；2K 双参考约 19.6 分钟，更多参考可能更慢。先用 0.5K/1K 检查内容；2K 上限不等于多图都能快速完成。

`manifest.json` 注册模型别名、图片类型、能力、依赖；`image_api.json` 是 API 格式模板，由表格动态填参数和参考节点。可用 ComfyUI API 提交，不是前端画布格式；如需可视化导入，使用上方官方画布模板。

文生图沿用用户提供的官方子工作流：原生 EmptyLatentImage → KSampler。ComfyUI 0.37.0 的采样入口读取 downscale_ratio_spacial 并适配 Qwen 的通道和空间压缩率；表格直接传入实际目标宽高。图生图现在也兼容官方 custom_size 逻辑：明确填写比例字段时，表格会创建 EmptyLatentImage 作为采样画布；未填写比例字段时，仍使用 TextEncodeQwenImage21 的原生 latent，跟随第一张参考图。无需额外安装切换插件。

检查：PowerShell 设置 `$env:COMFYUI_MODEL='qwen-image-2.1-local'` 后运行 `npm run check:comfyui`；协议回归 `npm run test:comfyui`。如果缺节点，升级 ComfyUI 核心；缺权重，核对名称/位置并重启；连接失败，核对运行实例、端口和表格端点。MiniMax 与 Qwen 若分属两个独立 ComfyUI，分别启动在不同端口并配置各自提供商；共用的自动启动 BAT 只能启动它所指向的一个实例。

## 本轮接入验证（2026-09-25）

以下为表格工程 ComfyUIClient 提交到本机 0.37.0 的实际结果，均 25 步、seed 20260925（2.7.2a 起补充图生图比例覆盖能力）：

| 用例 | 参数 | 实际输出 | 耗时 |
| --- | --- | --- | --- |
| 文生图 | 0.5K / 4:3 | 576×448 PNG | 14.1 秒 |
| 透明文生图 | 1K / 1:1 | 1024×1024 RGBA，alpha 0–255 | 32.2 秒 |
| 双参考图生图（未填比例） | 0.5K，两张不同图片 | 576×448，跟随首图 | 16.2 秒 |

4:3 的 0.5K 输出因为 32 对齐产生比例偏差（实际约 1.286），不是严格数学 4:3；与原生面积缩放一致。本轮没有重复运行高耗时的 2K 多参质量矩阵，2K 性能数据来自用户已有报告。

协议回归 17 项通过，包含 MiniMax 既有用例、Qwen 0/1/2/3/5 参考图、系数/越界、透明提示、PNG history 与图片/视频边界；预览策略 8 项通过；表格回归 44 项通过。生产构建通过。

隔离 Electron 实际表格验证：图片提供商注册、保留既有云端默认、透明模型建议、分辨率下拉、`{系数}` → `0.5`、图片生成请求和 Job 占位均通过。正式下载器从 ComfyUI 下载透明结果，扩展名为 PNG，文件字节与原图一致，alpha 保留。测试素材、截图和临时工具留在维护工作区，不进入工程工作流包。

既有检查限制：全量 Action API 测试中的版本断言仍写 2.6.8，与当前产品 2.7.1 不符；类型检查仍有 Grid.tsx 原有 TS2347（无类型调用带泛型）。此段记录为初次接入时的检查状态；2.7.2 已修正版本断言随 package.json 更新，类型检查问题仍单独记录。

## 2.7.2 参数兼容补充

- 图生图**未填写比例字段**时沿用首图；明确填写 `1:1`、`3:4`、`9:16` 等比例时，会创建 `EmptyLatentImage` 覆盖采样画布；比例下拉可用“自动（图生图跟随首图）”回到首图跟随模式。
- 文生图接收 `auto`（按 1:1）、中文冒号、空格和 `3:4 (Portrait Standard)` 标签；支持有效宽高比 1:8–8:1，按面积和32对齐生成。
- 分辨率仍是0.5–2的K系数；支持字符串K和数值引用，旧1024x1024配置兼容1K。它不是H3裸MP，也不接受4K。
- 生成数量沿用智能图片逐任务提交；参考图依次接入，不补齐。提示词、模型、原图、分辨率、比例、模式、画质都可引用字段。
- 旧表没有 mode/quality 时执行 standard/auto。新增API配置字段与图片预览同步。用户选择局部修图“保持原区域尺寸保存”时，现有保存后缩放仍有效；2K约束指采样分辨率。
- 改完后台代码必须完整重启 Electron，单靠 Vite 热更新不能刷新已导入的 ComfyUIClient。旧进程读取新manifest可能出现“1:1不支持画幅”，属于旧视频校验代码与新图片注册文件混用。
